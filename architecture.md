# Modular Synthesizer Sandbox - Architecture & Specification (v_5)

## 1. Overview
A browser-based, interactive modular synthesizer sandbox built with pure HTML5, CSS3, ES6 JavaScript, and the Web Audio API. Designed with a modular Eurorack-inspired workflow, clean visual aesthetic, responsive canvas routing, and support for audio processing, control voltage (CV) routing, and experimental modulation sources (such as Granular synthesis and Webcam tracking).

---

## 2. File Hierarchy & Roles

### Core Application & UI Logic
- **`index.html`**: Main entry point. Houses the DOM skeleton including the categorized floating Sidebar, Toolbar (a `Move` drag handle, Undo `#undo-btn` (&#8630;) and Redo `#redo-btn` (&#8631;) arrow buttons, Help, `Demo` `#demo-btn` (hidden until `onboarding.js` docks it), `Improbability` `#improbability-btn` (chaos button, `improbability.js`), Theme toggle, Presentation Mode, `Cables: Front/Back` toggle `#cable-layer-btn`, `Arrange` `#arrange-btn` (in the View menu), Zoom, Save/Load, Clear, Tooltips), Canvas Viewport overlay (`#connections-canvas`), Help & Presets Modal (`#help-modal`; under its tab content a small centered `p.help-copyright` line, `dir="ltr"`, "© 2026 noam bartov. All rights reserved.", 11 px, `--muted-text`, styled at the end of `styles.css`), `<meta name="author" content="noam bartov">` and `<meta name="copyright">` with the same text in `<head>`, and scripts loading order.
- **`styles.css`**: Complete application design system using CSS Custom Properties (`:root` / `.dark-theme`). Defines Clean White & Dark theme colors, module card layouts, wide granular card layouts, VU meter animations, cable canvas positioning (`#connections-canvas` `z-index: 30`, above `#workspace-viewport` `z-index: 1`; `body.cables-behind` drops the canvas to `z-index: 0` so cables go behind the modules), draggable panel handles (`.panel-drag-handle`, `.panel-dragging`), custom scrollbars, and modal layouts. Toolbar buttons that are `:disabled` (e.g. Undo with nothing to undo) are faded to 35% opacity. `index.html` loads it as `styles.css?v=3.3` and `app.js?v=12` (bump the `?v=` number on each change to defeat browser caching). End of file, "Patch organizing" block: `.module-card.chain-dimmed` (opacity 0.4; `.module-card` transition adds opacity 0.2 s, also kept in `.arranging`), `.module-renamed` (italic title), `.module-rename-input` (title-bar text field), `.mixer-ch-label` and its placeholder / focus styles.
- **`app.js` (`SoundSandboxApp`)**: Main controller class managing:
  - Global application state, module registry, and viewport Zoom/Pan (`Cmd`/`Ctrl` + Left-Click drag).
  - Web Audio Context initialization and user interaction audio unlock.
  - **Dynamic Cable Redrawing & `ResizeObserver` Integration:** Automated observation of DOM element size changes inside module cards (e.g., dynamically showing/hiding sliders like Pulse Width). Triggers immediate cable repositioning and canvas redraws (`drawConnections()`), alongside manual control via `updateCables()`.
  - **Template modules first:** `createModule()` first asks `ModuleBase.get(type)` (see `ModuleBase.js`); only if no template module is registered for that type does it fall through to the hand-written `if / else if` list of the original modules.
  - **Robust Instantiation & Webcam Fallback:** Enhanced type alias mapping (supporting `webcam`, `webcam_controller`, `webcam-controller`, `camera`) and graceful fallbacks/alerts if required module scripts are unmapped or missing.
  - Interactive cable connection drawing (dynamic Bezier curves color-coded by port type) on `#connections-canvas`; 3.5 px wide (6 px selected or in the highlighted chain), each cable longer than 60 px with a small arrowhead in its own colour at its middle pointing OUT → IN (`drawBezierCable(x1, y1, x2, y2, color, isSelected, style)`).
  - **Port lookup (`getPortElement(card, isOutput, info)`)**: searches only the ports of the requested direction (`.port-out`/`.output-port` or `.port-in`/`.input-port`), matching `info.channel` (`data-channel`) first, then `info.id || info.name || info.type` against `data-port-id`, then `data-port-name`, then `data-port-type`; falls back to the first port of that direction. When a port is pressed, the cable already plugged into it is found by comparing `getPortElement(...)` with the pressed element itself, never by port type alone (otherwise a free port of the same type, e.g. Keyboard `bend`, would pull out the `freq` cable).
  - **Multiple cables from one output (fan-out)**: dragging from an output port always starts a new cable, so one output can feed several inputs (e.g. both stereo inputs). `Shift`+drag from an output pulls out the most recently connected cable at that output (its input end stays put) so the source end can be moved. Dragging from an input port pulls out the cable plugged into it (inputs hold one cable each from the user's point of view). Dropping a cable that already exists (same output port to same input port) adds nothing.
  - **Port colors**: `updatePortConnectedClasses()` adds `.connected` to both ends of every cable and sets the CSS variable `--cable-color` on the port to that cable's color (`getConnectionColor()`); CSS paints the port and a ring in that color, so it is visible where each cable plugs in even with `Cables: Back`. Cable color is `getCableColor(portType, connId)` where `connId` combines both modules and both ports (`channel || id || name || type`), so two cables between the same two modules get different shades.
  - **Cable selection & deletion**: `drawConnections()` stores each drawn cable's Bezier points in `cableHitPaths`. A left click on the empty workspace runs `findCableAt(x, y)` (40-sample Bezier hit test, 8 px tolerance, topmost cable wins). First click selects (`selectedConnection`, drawn 6 px wide with a halo), a second click on the selected cable or `Delete`/`Backspace` deletes it (`deleteConnection()`), `Escape` or a click elsewhere deselects. Clicks inside a module card never reach cables, so moving a slider can never touch a cable.
  - **Cable layer toggle (`toggleCableLayer()`)**: `Cables: Front` (default, cables over modules) or `Cables: Back` (button highlighted, `body.cables-behind`). Remembered in `localStorage` key `sp_cables_behind`.
  - **Draggable panels (`initDraggablePanels()`)**: the Sidebar is dragged by its `Modules` title (`.sidebar h3`), the Toolbar by its `Move` label (`.toolbar .panel-drag-handle`). Positions are clamped to the window, saved in `localStorage` (`sp_panel_sidebar`, `sp_panel_toolbar`), and reset by double-clicking the handle. All `localStorage` access is wrapped in `try/catch`. A press only starts moving after 6 px of travel, so a tap is not a drag. **Phone layout** (`isPhone()`: `(max-width: 700px), (max-height: 500px)`, the same query as the PHONE block at the end of `styles.css`; iPad and desktop never match): the Toolbar is one strip across the top (8 px margins, buttons never wrap, swipe sideways for more buttons), and the Sidebar is 160 px wide below it (`top: 64px`). Tapping its `Modules` title opens or closes it (class `phone-collapsed`, shown as `Show`/`Hide` text after the title); it starts closed and the choice is saved in `localStorage` `sp_sidebar_phone_closed`. **Phone cable reach** (touch only, `isPhone()`; iPad and desktop unchanged): jacks are only a few pixels wide on a phone, so (1) a capture `pointerdown` on `#canvas-container` that lands within 22 screen px of a visible jack (inside `#workspace-viewport`, not on a jack, slider, select, button or text field) is stopped and re-sent as a synthetic `pointerdown` to the nearest jack (`findPhonePortNear()`), picking up a cable as if the jack itself was touched; (2) while a cable is dragged, `findCableSnapPort()` finds the nearest visible jack within 30 px that it can plug into (opposite direction, another module; none while over a `.knob-droppable` slider), the cable end jumps onto it and it gets `.port-snap-target` (filled in the text color with a ring, phone CSS block); (3) letting go anywhere off a jack plugs the cable into that lit jack. A jack counts as visible when `elementFromPoint` at its center is inside its own card.
  - **Collapsible Sidebar categories (`initSidebarGroups()`)**: each `.sidebar-group-title` is a framed, clickable row (`role="button"`, focusable, Enter/Space also toggle, `aria-expanded`) that opens or closes its group by toggling `.collapsed` on the `.sidebar-group` (CSS hides `.add-module-btn` children of a collapsed group). The title shows the number of modules in the group on the right (`data-count`, drawn by CSS `::after`, so the title's `textContent` stays the group name that `ModuleBase` matches); an open group's title is in the primary color. All groups start closed; the names of open groups are remembered in `localStorage` `sp_sidebar_open`. A delegated click handler on the Sidebar plus a `MutationObserver` keep this working for groups and buttons that `ModuleBase.register()` adds later. Text only, no arrow icons (design rule 3).
  - **Sidebar search (`#sidebar-search`)**: an `input type="search"` (placeholder `Search modules`) under the `Modules` title, handled in `initSidebarGroups()`. While it has text the Sidebar gets `.searching`: each `.add-module-btn` whose label or `data-type` contains the text (case-insensitive), or every button of a group whose title contains it, is shown even inside a closed category; the other buttons get `.search-hidden` and groups with no match `.search-empty` (both hidden); `p.sidebar-no-results` (`No modules found`) shows when nothing matches. Clearing the box restores the open/closed categories as they were. Enter adds the first match, Escape clears the box. Its `keydown` / `keyup` are stopped so typing does not play the Keyboard module or trigger app shortcuts. The `MutationObserver` re-runs the filter when template modules add buttons.
  - **Undo / Redo history (`initHistory()`)**: every history entry is a snapshot string from `takeSnapshot()` (modules sorted by id with `id`, `type`, `x`, `y`, `getState()`, plus all cables). `scheduleHistoryCapture()` runs 250 ms after any `pointerup`/`pointercancel`, `change` event, `keyup`, `deleteNode()`, `deleteConnection()` or a finished `loadPatchData()`; `captureHistory()` skips identical snapshots and waits while a pointer is still down or a cable is being dragged. Up to 100 steps (`undoStack`, `redoStack`; any new action clears redo). `restoreSnapshot()` changes only what differs: deletes extra modules, moves cards, calls `setState()` on modules whose state changed (rebuilding a module if `setState` cannot reach the old state, e.g. a removed mixer channel), creates missing modules with their original ids, removes the cables the snapshot does not have **before** any `setState()` (owner's report 2026-10-26: Undo / Partials 12 → 8 left the old sound on; a jack that `setState` removes from the card can no longer be found, and `getPortElement()` falls back to the module's first jack, so the cable's audio stayed plugged in and `disconnectAudio` unplugged the wrong jack), and after the modules adds the missing cables so `this.connections` matches the snapshot (`connectionKey()` = both modules + `channel ?? id ?? name ?? type` of both ports). Shortcuts: `Cmd/Ctrl+Z` undo, `Cmd/Ctrl+Shift+Z` or `Cmd/Ctrl+Y` redo (ignored while typing in a text/number field). Theme, zoom/pan and selection are not part of the history. Because snapshots are compared as text, `getState()` must return the intended values the module stored itself, never a live `AudioParam.value` (which lags behind ramps); Output (`this.volume`), VCA (`this.gainValue`) and Filter (`this.resonance`) follow this.
  - Module lifecycle (spawning, dragging, selecting, deletion with `unobserve`, clear canvas).
  - Presentation / Play Mode toggling (`isPresentationMode`).
  - Global tooltips state management (`toggleTooltips()`).
  - Module placement: a module added from the Sidebar is placed by `findFreeSpawnPoint()` at the free spot nearest the middle of the current view (candidate spots on a 30 px screen grid, sorted by the distance of the card's center from the free area's center) that is not under the Sidebar/Toolbar (`getFreeViewRect()`, works wherever those panels were dragged) and keeps 24 px from every other card; if the screen is full it goes to the right of all modules and the view pans to show it. The view never zooms. Once placed, the card gets the class `.module-spawned` (removed when its last animation ends): a 0.35 s pop-in (scale 0.9 → 1, fade in) and two 0.9 s amber ring pulses (`box-shadow` in the tips-ring orange `rgba(245, 158, 11)`); with `prefers-reduced-motion` only the ring. Modules loaded from presets or files (given coordinates) get neither.
  - `fitToModules(onlyIds)`: after any patch load, zooms (`minZoom()` to 1) and pans so all modules (or only the given ids: the modules of a preset just added) fit in the free screen area.
  - **Arrange (`arrangeModules()`, button `#arrange-btn` "Arrange" in the Toolbar's View menu)**: lays out every module by signal flow. Graph = `this.connections` (fromNode → toNode, LFO-to-slider cables included). **Rows mode (`arrangeRows()`, 2026-10-18)**: when any cable enters a Mixer channel (`toPortInfo.channel` or type `ch_in_N`), the layout is rows instead of wrapped columns. Each module's row set = the Mixer channels (`<mixerId>:<ch>`) it reaches going downstream over the loop-free edges, stopping at the first Mixer. Rows are ordered by each channel's path of channel numbers from the last Mixer (a Mixer that reaches no other Mixer; several of them ordered by rank, then top): a sub-mixer's channel `sub:k` feeding main `CH 3` has path `[main, 3, k]`, and when one path continues another the longer sorts first, so a sub-mixer's channel rows sit together just above the main channel row it feeds. A sub-mixer gets no row of its own: it stands in its column, centred on the span of its channels' rows. A module reaching exactly one channel goes in that channel's row; a module reaching several (decided walking from the end of the chain) joins the one row everything it feeds sits in (a voice's envelope), else a sound module (Sidebar category not Controllers/Modulation) takes the first of its rows (a voice sent to two effects), else (clock, Harmony Walker, sequencer) the shared row on top; reaching none: if its rank is past the last row column (or it is a Mixer) it goes to the right part (one column per rank, centred vertically on the rows: Mixer, effects, Output), otherwise into a "no Mixer" row under the channel rows; modules with no cables fill a last row left to right, wrapping at the patch width (min 900 px). Column x comes from rank (each column as wide as its widest module, 60 px gaps); several modules of one row in one column stack (24 px gaps, ordered by current top); 48 px between rows. Without any Mixer channel in use `arrangeRows()` returns null and the column layout below runs. Feedback loops are broken by a depth-first search (started from modules with no incoming cable, in left-to-right screen order) that ignores back edges. Column = longest path from the start of the chain; a module that only sends (Keyboard, LFO, Sequencer) is then moved to just left of the first module it feeds. Modules with no cables take a column from their Sidebar category (Controllers & Sequencing / Modulation = first, Sound Sources = middle, Processors & Effects = later, Output & Monitoring = last). `output` and `recorder` always take the last column. Inside a column, order starts from current `top`, then 6 barycenter passes (alternating by inputs and by outputs) put each module next to the modules it is cabled to, which keeps cables short and uncrossed; loose modules go to the bottom. A column taller than `targetH = max(tallest card, sqrt(total card area × free-screen height/width))` wraps into extra columns, so the patch keeps roughly the screen's shape. Gaps: 60 px between columns, 24 px between cards; each column is centred vertically; the layout starts at the patch's current top-left corner. The view is fitted to the new layout (`fitToModules()`), then the cards glide there (`.module-card.arranging` = 0.4 s `left`/`top` transition, cables redrawn every frame for 450 ms). One history entry, so Undo returns the old layout.
  - **Chain highlight (`onHeaderTap()`, `setFocus()`, `getChainIds()`, `applyFocus()`)**: a tap (pointer down and up on `.node-header`, moved ≤ 5 px, not on a button) sets `focusId`; so does a tap on an empty spot of the card (listener in `makeDraggable()`: the target is not in the header and not inside `input, select, button, textarea, canvas, svg, a, label, video, [contenteditable], [role=button], .port, .module-resize-handle`, its computed `cursor` is `auto`/`default`, the pointerdown was not `preventDefault`ed by the module, and the pointer moved ≤ 5 px). Chain cables draw 6 px wide instead of 3.5 px. The chain = everything downstream of the module, plus everything upstream of the module and of its downstream modules before the first Mixer (so a voice's clock and envelope light up, the other Mixer channels do not; tapping a Mixer itself lights its whole chain). `drawConnections()` calls `applyFocus()`: cards outside the chain get `.chain-dimmed` (opacity 0.4), cables not between two chain modules draw at `globalAlpha` 0.12 (a selected cable stays bright). Off when the module has no cables, in Play Mode, after a tap on the empty canvas or Escape, or when the module is deleted. Not saved.
  - **Module rename (`startRename()`, `setModuleName()`, `getModuleName()`)**: a second header tap within 400 ms (double tap / double click) puts an `input.module-rename-input` (max 32 chars) in place of the title `<span>` (the first `span` of `.node-header`, every module has one). Enter or blur saves, Escape cancels; its pointerdown and keydown do not reach the canvas or shortcuts. The original title is kept in `span.dataset.defaultTitle`; an empty name or the original title clears the rename. A renamed title is italic (`.module-renamed`) with a tooltip naming the original. The name is `this.modules[id].name`, written as `name` (only when set) in history snapshots (`takeSnapshotRaw()`, applied in `restoreSnapshot()`) and saved patches (`getPatchObject()`, applied in `loadPatchData()`), so Undo and Save/Load keep it.
  - **Mixer channel hints (`updateMixerHints()`, `getChannelHint()`)**: if the cable's source module has `getMixerHint(fromPortInfo)` and it returns text, that text is the hint (Harmonics: interval names per jack, 2026-10-25); otherwise run at the end of `updatePortConnectedClasses()` and after a rename. For each Mixer channel with a cable, the hint is the nearest renamed module up its chain (breadth-first, not through other Mixers), else the first module from the Sidebar's Sound Sources group, else the module plugged in, with any trailing "(...)" dropped; passed to `MixerModule.setLabelHints()`.
  - `loadPatchData(patch, opts)`: without options (the Load button) it clears the workspace and recreates the patch with its own ids, positions and theme. With `{ add: true }` (presets from the manual) on a non-empty canvas it keeps everything, ignores the patch theme, gives each new module a fresh id (`<type>_<time>_<random>`) and remaps the cables to them (a slider-cable `knob` ref ending in the old module id is rewritten too), and shifts the patch so its left edge is 120 px right of the existing modules and its top matches theirs. It returns the ids of the modules it created.
  - **No hidden modules on load (`separateOverlaps(ids)`, owner's request 2026-10-25)**: run by `loadPatchData` after the cables are made (cards have their real sizes then). The new cards, sorted left to right then top to bottom, are placed one by one; a card whose rectangle overlaps a card already placed (the modules that were on the canvas, or new cards placed before it) moves right to 30 px past that card, again until it overlaps nothing; its `top` never changes. Cards that only sit close together are not moved. So a preset or file never opens with a module hidden under another, whatever the cards' real widths (e.g. the Keyboard is 620 px).
  - **Make room when a module grows (`makeRoomFor(ids)`, owner's request 2026-10-25)**: called after a card got bigger (Harmonics Partials, the Mixer channels it added). The grown cards stay put; every other card that now overlaps one of them glides (`.arranging`, cables redrawn for 450 ms) right or down, whichever is the shorter move, to 30 px past it, and pushes on in turn (moves only go right / down, so it ends; 500 steps at most). Afterwards, if a grown card is partly outside the free part of the screen (`getFreeViewRect()`), the view zooms out with `fitToModules()` to show the whole patch (on iPad too). One history entry.
- **`audioEngine.js`**: Centralized Web Audio engine wrapper. Standardizes `AudioContext` management, master input/output node routing, global volume control, and dynamic hardware sample rate detection.
- **`touchSliders.js`** (loaded right after `audioEngine.js`): every `input[type="range"]` is driven by Pointer Events for fingers and the pencil (`pointerType` not `mouse`), because iPad Safari's own slider handling stops while another finger is down (e.g. holding a Keyboard key while moving a Poly Synth slider). A capture-phase `touchstart` listener calls `preventDefault` on sliders (native handling off); `pointerdown` (document, capture) records the slider, start point and start value and takes pointer capture; `pointermove` sets `value = start + moved / track length × (max - min)`, snapped to `step` and clamped, then fires `input` (bubbles); `pointerup` / `pointercancel` fire `change`. The drag is relative (the full track length = the full range, a tap does not jump). Vertical sliders (computed `writing-mode` starting with `vertical` / `tb` / `bt`, or taller than 1.5 × wide) go up for more. Each pointer drives its own slider, so several sliders and keys work at once. Mouse dragging stays native.
- **`valueEntry.js`** (loaded right after `touchSliders.js`; owner's request 2026-10-25): **typing exact slider values**. A tap / click on a slider's number (any element with `data-entry` inside a `.module-card`; a click that ends a drag of more than 6 px is ignored) hides it and puts a `span.ve-box` after it: `span.ve-field` (`input.ve-input`, type text, `inputmode="decimal"`, or `text` when the range goes below 0 or the readout is not a plain number, since iPad's decimal pad has no minus; plus `span.ve-unit`) and, only when the last `pointerdown` was a finger or pencil, `span.ve-steps` with two `button.ve-btn` `−` / `+` (pointerdown steps once, holding repeats after 420 ms every 70 ms; `touchstart` / `pointerdown` are prevented so the box keeps focus and the iPad keyboard stays open). Enter or leaving the box (blur) sets the typed value, Escape restores the value from when the box opened, Arrow Up / Down step once (Shift: 10 steps) and are applied at once; every key event is stopped at the box, so Keyboard-module notes, Delete and the canvas shortcuts do not fire while typing. A comma counts as a decimal point; a value outside the range stops at the nearest end; unreadable text changes nothing. **Pairing**: the slider is the only `input[type=range]` in the nearest ancestor of the readout that has one (stopping at the card). **Settings** in `data-entry`: either inline `key:value;key:value` with `scale` (shown number = slider value × scale, default 1), `unit` (text after the box; default: the readout's text without its number), `step`, `decimals`, `prop` (the module property holding the exact slider value, e.g. Envelope `prop:attack`); or `@key`, and the module's `getEntry(key, slider)` returns an object with the same fields plus `toSlider(n)` / `fromSlider(v)` for curved sliders, `get()` (exact current slider-space value) and `format(n)` / `parse(text)` for readouts that are not plain numbers. The box opens on the exact value (last typed value while the slider still holds it, else `get()` / `prop`, else the slider), rounded to `decimals` (default: the decimals of the step, 2 for curved sliders). Arrow / button step: `step` in shown units (default slider step × scale), or for curved sliders without `step` one slider step. **Writing**: the slider's `step` is set to `any` for that moment so the value is exact, `value` is set and `input` + `change` are dispatched, then `step` is restored; so each module's own slider code, LFO-to-slider cables (the typed value becomes the new base), undo history and saving all work unchanged. Which readouts take part: every ModuleBase slider (`entryAttr(p)` in `renderControl` and the EQ grid), Stereo Delay cells, Drum Machine knobs and Swing, and in the hand-written modules: Oscillator Frequency (`@freq`, Hz, 1 Hz steps), Pulse Width and Slope (`scale:100`), Filter Cutoff (`@cutoff`, on the outer span around the number and `Hz`), Q, Mod Depth, LFO Rate (`@rate`, 0.1 Hz steps) and Depth, Envelope A/D/R (`scale:1000;unit:ms;prop:…`) and S, Granular (six), Reverb (five), VCA, Output, Mic / Audio In level, Sequencer Tempo and Octave, Webcam (three), Mixer channel and master volume. Not included: sliders with no number (Keyboard Slide and Pitch wheel, Sequencer step pitches, Mixer Pan), Metronome / Drum Machine tempo (they already have a number box). Styles at the end of `styles.css`: `[data-entry]` has a text cursor and a dotted underline on hover (mouse only), `.ve-box` (inline-flex, wraps, centred), `.ve-field` / `.ve-steps` (no wrap), `.ve-input` (44 px, 11 px bold, `--muted-text` border, `--panel-bg`), `.ve-unit` (`--muted-text`), `.ve-btn` (26×22 px, 14 px bold, `--btn-border`, `--subtle-bg`, `touch-action: none`). `window.ValueEntry.startEdit(readout)` opens a box from code.
- **`clockSync.js`** (loaded right after `touchSliders.js`, before every module): the shared way to follow a CLOCK cable (section 4), `window.ClockSource` and `window.ClockFollower`. **`ClockSource`**: `ClockSource.attach(node)` puts `node.clockSource` on a source's CLOCK output node (Metronome, Drum Machine, Sequencer); the source's look-ahead scheduler calls `clockSource.pulse(time, dur, first)` for every 16th it schedules (`time` = exact audio time of the pulse, `dur` = seconds per 16th, `first` = playback just started; it keeps `index`, 0 on the first pulse) and `clockSource.stop()` when it stops or is deleted. **`ClockFollower(ctx, { onPulse(time, dur, index), onStop(), onCablesChanged(count) })`**: `follower.input` (a GainNode) is the module's CLOCK input node; the module calls `follower.cable(connected, source)` from `onInputConnected` (counts cables; when `source.clockSource` exists it subscribes to it). Two paths: (1) announced pulses from a subscribed ClockSource arrive ahead of time with exact times, so followers schedule on the same audio time as the source (sample-accurate, measured 0 ms offset), start at `index` 0 and stop on `stop()`; (2) any other gate signal goes through the AudioWorklet `clock-edge-processor` (made from a string, loaded once per context; rising edge above 0.5, re-armed below 0.25, posts the edge's audio time; a silent gain to `destination` keeps it running), used only while no announcing source is plugged in: `dur` = time since the previous edge (0.125 s until known), a gap over 1 s (or the first edge) is a start (`index` 0), the pulse is played at `max(edge, now)` (a few ms late), and a watchdog calls `onStop` after `max(1 s, 4 × dur)` without edges. Removing the last cable (or the last announcing source) calls `onStop`. `follower.connected` = at least one cable; `follower.destroy()` on module delete.
- **`PatchManager.js`**: Handles JSON serialization and deserialization of synthesizer patches (saving canvas layouts, module parameters, active settings, and cable wire connections). **Note:** this file is currently *not* loaded by `index.html`; the live save/load logic is `exportPatch()` / `loadPatchData()` inside `app.js`.
- **`portGuide.js`**: Jack hints. Holds `GUIDE`, the single table of every jack (key `<moduleType>:<in|out>:<portKey>`, where portKey is `data-port-id` || `data-port-name` || `data-port-type` || `default`, mixer channel numbers dropped) with its name, signal kind, a one-line explanation, where to connect it from/to, and a `match` list of recommended partner jacks. Shows a themed `.port-hint` card 250 ms after the pointer rests on a jack (replaces the native `title`, follows the Tooltips ON/OFF button via `body.tooltips-disabled`). While a cable is dragged (reads `synthApp.activeCable` on capture-phase pointerdown) it adds `body.cable-dragging` and marks every jack: `.port-suggested` (recommended partner, pulsing primary ring), `.port-compatible` (opposite direction on another module), `.port-incompatible` (faded). Always-visible labels: while Tooltips is ON (and not in Play Mode or with Help open) every jack gets a small tag under it in `#port-chip-layer` (a fixed layer, z-index 90, above the canvas and below the Sidebar/Toolbar, because cards clip their contents; on a phone z-index 29, under the cable canvas but still above the modules, so cables are never hidden behind a label): `IN`/`OUT` (inputs outlined, outputs filled in the primary color), the signal kind, and a `from …` / `to …` hint from the `CHIPS` table. - **`modulation.js`** (loaded right before `app.js`): `KnobModulation`, "LFO to any slider". A cable from LFO OUT dropped on any `input[type="range"]` of another module is stored as a normal entry in `app.connections` with `toPortInfo: { id: 'knob:<ref>', knob: '<ref>' }`, where `<ref>` is `#<slider id>` or `i<index among the card's sliders>` (`refFor()` / `resolve()`). `app.js` creates `this.knobMod`; `connectAudio` / `disconnectAudio` call `knobMod.add()` / `remove()` for such cables instead of Web Audio connections; `getPortElement(card, false, info)` returns the slider for `info.knob`, so drawing, deleting, undo and saving reuse the normal cable code; `getPortCenter()` ends such a cable at the slider's left end. The base is what the user set: if the slider's value differs from the last value the loop wrote (user drag, undo, `setState`), that becomes the new base. `withBaseValues(fn)` puts every modulated slider at its base while `fn` runs (used by `takeSnapshot()` and Save, so history and saved files hold the user's values; the modulated value is written back in the same task). ### Audio Processing & Generation Modules
- **`OscillatorModule.js` (VCO)**: Primary sound source (`OscillatorNode`). Features waveform selection (sawtooth, square, triangle, sine), pitch tuning, fine tune, octave controls, pulse width modulation, a `PITCH` input (`data-port-type="pitch"`, a GainNode into `frequency`) and an `FM IN` input (straight into `frequency`). While at least one cable is plugged into PITCH (`onInputConnected('pitch', true)` counts them), the base frequency is held at 0 so the incoming Hz value (Keyboard FREQ, Sequencer PITCH CV) plays exactly in tune, the Frequency slider is disabled and its label reads `from PITCH IN`; unplugging restores the slider value. FM IN adds to the current pitch (vibrato, FM). The Frequency slider runs 0 to 1 (step 0.001) and maps to 20 to 4000 Hz through `OscillatorModule.sliderToFreq` / `freqToSlider`: `freq = 20 * 200^(pos^k)`, with `k` chosen so the midpoint (0.5) reads 200 Hz. The patch JSON stores the frequency in Hz, not the slider position. **Sawtooth shape** (shown only while Waveform is Sawtooth, `#saw_container_<id>`): a `Slope` slider (`#osc_rise_<id>`, 0-1, step 0.01, default 1, readout `Rise n% / Fall m%`) sets `sawRise`, the share of each cycle spent rising from the bottom to the peak (1 = classic saw, 0.5 = triangle, 0 = falling ramp), and a `Flip: On/Off` button (`#osc_flip_<id>`, `action-btn module-toggle osc-flip`, `.active` when on) sets `sawFlip` (wave upside down). With Slope 100% and Flip off the browser sawtooth goes straight to the output, exactly as before; otherwise the oscillator plays a band-limited `PeriodicWave` from `makeSawWave(rise, flip)`, built from the Fourier series of the shape (harmonics 1-1024, `OscillatorModule.SAW_HARMONICS`): for 0 < rise < 1, with `A = 2/(rise(1-rise))`, `θ = 2πn·rise`, `k = 2A/(4π²n²)`: cosine term `-k(1-cos θ)`, sine term `k·sin θ`; at rise 1 / 0 the plain ramp `∓2/(πn)` sine terms; every harmonic n is multiplied by `(-1)^n` (half a cycle shift, so the shaped saw lines up with the browser sawtooth, which starts mid-ramp), and all are negated when flipped. **Two sides (A / B)**: the module has two `OscillatorNode`s (`oscNode` = A, `oscB`), started at the same time and always given the same frequency (base frequency on both, `pitchInput` and `fmInput` connect to both `frequency` params; `fmInput` is a GainNode), so they stay in phase; each goes through its own side gain (`sideGainA` 1 / `sideGainB` 0) into `mixNode`, which feeds the Pulse Width `WaveShaperNode` (Square) or the output. A Waveform menu change (`updateWaveformRouting`) sets the wave on both sides at once and side A is heard. A Slope or Flip change (`crossfadeToSaw`) sets the new shape on the silent side and the side gains crossfade linearly over `OscillatorModule.FADE` (30 ms); while a fade runs the newest shape waits and is applied right after it (one `setTimeout`, cleared in `cleanup`), because swapping the wave of a sounding oscillator jumps mid-cycle and clicks (dragging Slope, Flip, an LFO on Slope). While the AudioContext is not running the shape is set on both sides at once. Waves are cached per AudioContext by rise (2 decimals) and flip (`OscillatorModule.sawWaves`). Do not shape the browser sawtooth with a WaveShaper for this: its band-limited jump passes through the middle values once a cycle and the curve turns them into a spike (heard as clicks). State: `{ waveform, frequency, pulseWidth, sawRise, sawFlip }`; older patches without the last two load as a classic saw. Changing the Waveform calls `synthApp.updateCables()` because the card height changes.

- **`EnvelopeModule.js` (EG)**: ADSR Envelope Generator. Controls: Attack, Decay, Sustain, Release. The envelope is drawn sample by sample in an AudioWorklet (`ADSR_WORKLET`, processor `adsr-env-processor`, registered once per page through the shared promise `EnvelopeModule.workletReady`) whose input is the gate (on above 0.2) and whose output goes to `outNode` (a GainNode, the module's ENV OUT). Straight-line segments: Attack from the current value to 1, Decay to Sustain, hold (follows Sustain changes smoothly), Release from the current value to 0; each time at least 3 ms. The slider values reach the worklet by `port.postMessage` (`sendParams()`). Running in the audio thread, a note starts exactly when the gate rises; scheduling from the main thread at `ctx.currentTime` (the old way) started from a stale time and sometimes jumped to the top of the attack in one sample (a click, measured as 2 jumps of about 0.47 in 6 s of `demo-reverb`). Without AudioWorklet support, a main-thread fallback (an Analyser polled every 12 ms) draws the same lines on a ConstantSource (`envNode`, also into `outNode`) with `this.points` remembering their corners, so a new gate starts from the current value without `cancelAndHoldAtTime`.

- **`ReverbModule.js`**: algorithmic reverb. Controls: Radius (1-50 m, 15), Decay (0.2-12 s, 3.5), Damping (500-16000 Hz, 4000), Warp (0-100%, 25), Mix (0-1, 0.4). Dry path: IN L → OUT L, IN R → OUT R; while IN R has no cable (`onInputConnected('in_r')` counts them in `inRCables`) IN L also feeds the right dry gain, so a mono source stays centered (`monoDryR`). The room's stereo output is split (`ChannelSplitter`) so its left channel goes to OUT L and its right channel to OUT R. Wet path: L+R → lowpass (Damping) → WaveShaper (Warp) → `roomIn` → the room, an `AudioWorkletNode` `reverb-room` (code in the `REVERB_WORKLET` string at the end of the file, loaded once per audio context from a Blob URL by `ReverbModule.loadWorklet`; mono in, stereo out, AudioParams `radius` and `decay`, k-rate) → `roomOut` → wet gains. Until the worklet loads the wet path is silent. The room: 4 allpass filters in a row (4.8, 3.6, 12.7, 9.3 ms, g 0.7) for diffusion, then 8 delay lines (29.7, 37.1, 41.1, 43.7, 53.3, 59.9, 67.7, 73.1 ms × size, size = 0.25 + Radius / 50 × 1.75) fed back through a Householder matrix (y = x − 2/8 × sum), each with a one-pole low-pass (coefficient 0.6) in its loop and feedback g = 10^(−3 × length / (Decay × sampleRate)) (the tail falls 60 dB in Decay seconds); the input goes into every line with alternating sign; even lines are the left output, odd lines the right, scaled by 0.29 × sqrt(1 − mean g²) so a longer Decay is not much louder (ramped per block). Line lengths glide to a new Radius with a ~40 ms time constant (linear-interpolated reads) and Decay applies every block, so both sliders move smoothly with no rebuild or crossfade (`updateRoom()` only sets the two AudioParams). `cleanup()` tells the worklet to stop (`'stop'` message, `process` returns false) and disconnects it.
- **`GranularModule.js`**: Advanced Granular Synthesis engine. Real-time grain extraction from loaded audio files. Controls for Grain Size, Density, Pitch, Spray (Jitter), Grain Pan, and dual assignable CV modulation inputs (`cv1`, `cv2`). Default source mode `live`: IN L/R are recorded into a 5 s ring buffer every 15 ms; each tick copies exactly the samples that arrived since the previous tick (the newest part of the 2048-sample analyser window), so the buffer is continuous. Without an input it is silent. `density` is grains per second (integer). Source `file`: **Load File** opens a hidden file input whose `accept` is `GranularModule.FILE_ACCEPT` (`audio/*` plus every common audio extension and MIME type: mp3, wav, m4a, aac, mp4, ogg, opus, flac, aif/aiff/aifc, caf, webm), because iPad / iPhone pickers grey out files that only match a bare `audio/*`. `loadFile(file)` reads it and tries the browser's `decodeAudioData`; if that fails it falls back to `GranularModule.decodePcm()`, a small parser for uncompressed WAV (8/16/24/32-bit int, 32-bit float), AIFF / AIFF-C (`NONE`, `twos`, `sowt`, `fl32`) and, since 2026-10-25, CAF with `lpcm` data (`desc` chunk: float64 rate, flags bit 1 = float, bit 2 = little-endian, channels, bits; `data` chunk after its 4-byte edit count; 8/16/24/32-bit int or 32-bit float), so AIFF and CAF (Logic's sample folders) work in Chrome and Firefox too. If both fail, a toast gives `GranularModule.unreadableReason(data, name)` when it knows one (a `.exs` Logic instrument file: "This is a Logic instrument file (.exs), not a sound. Pick one of its sample files instead (.aif, .wav or .caf)."; a CAF whose `desc` format is `alac`: "This .caf file is Apple Lossless, which this browser cannot read. Open the site in Safari, or export the sample as WAV or AIFF."), otherwise says the file could not be opened and lists the supported types. `decodePcm`, `unreadableReason` and `FILE_ACCEPT` are shared by Granular, Sampler and Timbre.

The table is posted to the AudioWorklet `wavetable-processor` (from a string through a Blob URL, one shared promise) whenever Table changes. **Worklet** params: `freq`, `fm`, `pos`, `posmod` (a-rate; `PITCH`, `FM` and `POS` are connected into `freq`, `fm`, `posmod`), `ratio` = 2^(Octave + Tune/1200), `warp`, `voices` and `detune` (k-rate). Unison: voice v of n plays at f × 2^(detune × (2v/(n-1) - 1) / 1200) (evenly spread from -Detune to +Detune cents), each with its own phase (voices after the first start at a random phase), and the sum is scaled by 1/√n. Per sample: f = freq × ratio + fm; level = ceil(log2(|f| × highest voice ratio / 40)) clamped to 0..9; each voice's phase accumulates its frequency / sampleRate; Warp is phase distortion (`k = 0.5 - 0.45 × warp`; phase < k maps to 0..0.5, the rest to 0.5..1); position = clamp(pos + posmod, 0, 1) picks two neighboring frames, read with linear interpolation and crossfaded. About every 2048 samples the worklet posts the current position when it moved. **Display** (`canvas.wt-display`, 480 × 240 drawn at 100% × 120 px): the 8 frames of level 0 stacked in pseudo-3D (first wave front-left-bottom, last back-right-top, muted lines), and the wave playing now (with Warp applied) in the primary color at its place in the stack; redrawn on Table / Position / Warp changes and on position messages. **Draw table**: the card keeps a drawn cycle of 128 points (-1..1, starts as a saw, `WT_DRAW_N`); while Table is Draw the display shows it flat (text color, 3 px, with a midline) with the wave playing now over it (primary, 2 px), the canvas gets `.wt-drawing` (crosshair, `touch-action: none`) and the hint `div.wt-hint` under it is shown ("Draw a wave with the mouse or pencil. Position 0% plays a sine, 100% your wave."). Drawing (pointer events with pointer capture, propagation stopped so the canvas does not pan) sets every point between the last and the current x (linear); on release the drawing is turned into harmonics 1-63 by a plain DFT (`waveToHarmonics`, DC dropped), the Draw table is rebuilt (not cached; `buildTable(name, sampleRate, drawn)`) and posted to the worklet. State: the params plus `drawn` (128 numbers, 3 decimals).
- **`PolySynthModule.js`** (template module, type `polysynth`, Sidebar group Sound Sources, 240 px card): a complete polyphonic synth. Also defines `PolyNoteBus` (`window.PolyNoteBus`, used by the Keyboard). **Jacks**: `NOTES` (input, signal `gate`; its input node is a plain object with `noteOn(note, freq)`, `noteOff(note)`, `allNotesOff()`), audio `OUT` (`outNode`, gain 0.35 × Level). **Controls**: `Voices` (1-8, 8), `Waveform` menu (`wave`: sawtooth, square, triangle, sine, or a Wavetable Osc table: `wt_basic`, `wt_vocal`, `wt_digital`, `wt_organ`, `wt_pwm`; the Draw table is not offered), `Position` (0-100%, step 0.5, 0) and `Warp` (0-100%, 0), both `disabled` while a plain wave is chosen, `Detune` (0-50 cents, 8; osc 1 at -Detune/2, osc 2 at +Detune/2), `Cutoff` (`cutoff` 0-100 → 60 × 200^(v/100) Hz, i.e. 60 Hz to 12 kHz, readout in Hz / kHz, 45), `Resonance` (`reso`, Q 0-20, 2), `Filter Env` (`filterEnv` 0-100%, 40: the filter opens to Cutoff × 2^(6 × Filter Env), max 18 kHz, at the top of the attack), `Attack` (1-3000 ms, 10), `Decay` (10-3000 ms, 400), `Sustain` (0-100%, 60), `Release` (10-5000 ms, 500), `Level` (0-100%, 70). **Voices**: 8 voices built once and always running, each two `OscillatorNode`s (osc 1, osc 2) → GainNode 0.5 → lowpass `BiquadFilterNode` → amp GainNode (0 when silent) → `outNode`. Note on: the voice is chosen as the same note if it still sounds, else a free voice (released and past its release time), else the one released longest ago, else the oldest held note; only the first `Voices` voices are used. A voice still sounding another note (held, or before the end of its release) is "stolen": its amp first goes `setTargetAtTime(0, now, 2 ms)` and the new note starts 8 ms later. **Envelopes use only `cancelScheduledValues(now)` + `setTargetAtTime`** (it starts from wherever the value is), never `cancelAndHoldAtTime` + linear / exponential ramps: in Chrome a ramp scheduled after `cancelAndHoldAtTime` during a release jumps (a loud click whenever a note is played while an earlier one rings out), and cancelling a running ramp jumps back to its start. Amp on note: `setTargetAtTime(1, start, Attack / 3)` (95% at the end of Attack), then `setTargetAtTime(Sustain, start + Attack, Decay / 4)`. Filter on note: `setValueAtTime(Cutoff, start)` only when the voice was silent or stolen, then `setTargetAtTime(peak, start, Attack / 3)` and `setTargetAtTime(Cutoff + (peak - Cutoff) × Sustain, start + Attack, Decay / 4)`. Note off: amp and filter `setTargetAtTime` to 0 / Cutoff with time constant Release / 4, the voice is free after Release. Moving Cutoff / Filter Env / Sustain during a held note: `cancelScheduledValues` + `setTargetAtTime(…, 30 ms)`. **Two sides (A / B) per voice**: each voice's osc 1 + osc 2 exist twice, side A and side B, each pair into its own side GainNode (A at 1, B at 0) → the voice's 0.5 GainNode; all four oscillators start at the same time and always get the same frequency and detune (`osc1s` / `osc2s`), so the sides stay in phase. **Wavetables** (`applyWave`): the wanted wave (plain: `osc.type`; table: one `PeriodicWave`) is identified by a key (wave name, or table|Position|Warp) and only applied when the key changed. `flushWave()`: the first wave (or any while the AudioContext is not running) is set on both sides at once; after that it is set on the silent side and the side gains crossfade linearly over `POLY_WAVE_FADE` (30 ms) on all voices, because swapping the waveform of a sounding oscillator jumps mid-cycle and clicks (e.g. an LFO on Position or Warp). While a crossfade runs, the newest wave waits (one `setTimeout`, cleared in `destroy`) and is applied right after it, so at most ~30 swaps a second. `PolySynthModule.tableWave(ctx, table, pos, warp)` builds it from `WT_TABLES`, `WT_FRAMES`, `WT_MAX_H` (globals of `WavetableModule.js`, which loads first): `tableFrames(table)` computes the 8 frames' harmonics, each scaled to a peak of 1 (cached per table); the two neighboring frames are blended at Position (like the Wavetable Osc's crossfade); with Warp > 0 one cycle is rebuilt (inverse FFT, 2048 samples), read with the Wavetable Osc's phase distortion (`k = 0.5 - 0.45 × warp`, linear interpolation) and turned back into harmonics 1-256 (FFT, `PolySynthModule.fft` radix-2); then `createPeriodicWave(real = cosine terms, imag = sine terms)`, which the browser band-limits and scales to a peak of 1. Waves are cached by table, Position (3 decimals) and Warp (2 decimals), up to 600 (then the cache is cleared), so an LFO on Position costs about 1 ms per new value. Changing Cutoff / Filter Env / Sustain moves held notes (past their attack) to the new sustain values; lowering Voices releases the voices above it. **Keyboard Slide and pitch bend over NOTES**: a started `ConstantSourceNode` `bendNode` is connected to the `detune` of all 32 oscillators; `setBend(amount)` sets it to `amount × 200` cents (`setTargetAtTime`, 5 ms), so the wheel bends every voice up to ±2 semitones; `allNotesOff()` resets it to 0. `noteOn(note, freq, glide)`: when the voice already holds this same note (`gate` on), it is legato: the oscillators go from the voice's `freq` to the new Hz (`setTargetAtTime`, glide / 3, or at once with no glide) and the envelopes are not started again (used by the Harmony Walker's Glide). Otherwise, with `glide` > 0 s (`true` from older callers = 0.15 s) and a previous note (`lastFreq`, the Hz of the last note played), the voice's oscillators start at `lastFreq` and `setTargetAtTime(freq, start, glide / 3)`; otherwise they jump to `freq`. **Display**: `div.poly-voices`, 8 numbered cells `div.poly-voice` (`.on` while the voice holds a note, `.off` = 30% opacity above the Voices count). State: the params only.

Alto = tintinnabuli voice: the nearest tonic-triad note below the melody note (With Contrary: above on every other note; No crossing then moves that one an octave down, or takes the one below; No 5ths/8ves: never the melody's own pitch class above / pitch below; Common tones: keeps its last note while it stays on the right side within a sixth). Tenor: the melody mirrored in the scale around the tonic an octave below (With Contrary) or a tenth below. Bass: the tonic as a drone, struck again at every phrase. Leading tone raises the note under the tonic when the melody rises into it. A chord arriving while stopped (and no CLOCK) starts it. **Playing**: a 16th-note tick, from its Tempo (a 25 ms scheduler, 0.1 s ahead) or from the `ClockFollower` (starts at the source's start, index 0 starts over, stops with it; Play is disabled meanwhile). Free writes the next phrase when one ends; Melody loops. NOTES and the display follow each tick at its audio time. ## 3. Strict UI, Visual & Audio Preferences (Design Rules)

### 1. No Icons in Modules Rule (כלל איסור אייקונים במודולים)
- **חוק ברזל:** אין להשתמש באייקונים או אימוג'ים בתוך רכיבי המודולים (כותרות מודול, כפתורי תפעול, כפתורי מחיקה, תפריט Sidebar, או תוויות פורטים).
- **חלופה:** יש להשתמש בטקסט שמי קריא בלבד (לדוגמה: "Delete" או "X" במקום אייקון פח, "Audio Input" במקום אייקון מיקרופון, "Oscillator" במקום אייקון גל).

### 2. Design System & Theming
- Fully implemented via CSS Custom Properties (`--bg-color`, `--panel-bg`, `--primary-color`, `--panel-border`, `--text-color`).
- Clean White light theme as default with full Dark Theme support toggled via `.dark-theme` on `<body>`.
- **Every module follows the theme.** Module markup and canvas drawings never hard-code light or dark colors: backgrounds, borders and text use the theme variables (`--panel-bg` card / inner boxes, `--subtle-bg` displays and screens, `--panel-border` lines and boxes, `--btn-bg` / `--btn-border` controls, `--text-color`, `--muted-text`, `--primary-color` live traces and highlights). A module that paints a `<canvas>` reads these with `getComputedStyle(card)` when it draws, and `app.toggleTheme()` calls `onThemeChange()` on every module so it can repaint (ModuleBase's default calls `requestDraw()` when the module has one; Granular redraws its waveform; the Oscilloscope re-reads its colors). Fixed colors are allowed only for signal color coding (jack rings, meter green/red) and for deliberate instrument looks that read in both themes (the Keyboard's slate case with ivory keys, the Ribbon's rainbow strip). Checked by creating every module in a headless browser and comparing both themes.
- Modular cards use explicit shadow layers (`var(--shadow-sm)`), smooth border transitions (`var(--transition-fast)`), and rounded corners (`var(--radius-lg)`).

### 3. Module Card Structure & Constraints
- **Card Width**: Standard modules must maintain a `min-width: 220px` (or `width: 220px`). Large modules (e.g., Granular Engine) use wide double-panel grid layouts (`width: 500px`).
- **Vertical Flex Layout**: Card body (`.node-body`) uses flexbox layout (`flex-direction: column`, `padding: 12px`, `gap: 10px`).
- **Ports Container Docking**: The ports section (`.ports-container`, `.ports-row`) **must always** use `margin-top: auto` to dock ports cleanly at the bottom of the card, preventing text overlapping or card overflows.
- **Control Uniformity**: Standard buttons use `.action-btn`. Continuous range inputs (`input[type="range"]`) must always include an accompanying numeric text readout displaying the active unit (`Hz`, `ms`, `%`, `dB`).

### 4. Accessibility & Focus Indicators
- Clear keyboard focus indicators (`*:focus-visible`) styled with `outline: 2px solid var(--primary-color)`.
- Customized scrollbars (`::-webkit-scrollbar`) styled to blend seamlessly with active themes.

### 5. Language Rule
- The whole site UI is English only: toolbar, sidebar, modules, notifications, `alert`/`confirm` dialogs, and `<html lang="en">`.
- Hebrew exists only as an optional second language, English always being the default: inside the Help manual (`helpData.js` `he`, the Hebrew button) and in the empty-canvas explanation (`onboarding.js`, the "עברית" button; added at the owner's request on 2026-10-17 because many users speak Hebrew). ## 4. Signal Flow & Port Color Coding System

### Signal Types & Port Specifications
- 🟢 **Audio Signals (`data-port-type="audio"`):** Green (`#10b981`). Sound-generating audio paths (e.g., VCO Out &rarr; VCF In &rarr; VCA In &rarr; Reverb In &rarr; Main Output).
- 🟡 **Gate / Trigger Signals (`data-port-type="gate"`):** Yellow/Orange (`#f59e0b`). On/Off timing pulses generated by Keyboard or Sequencer to trigger Envelope attack phases.
- ⏱ **Clock convention (`CLOCK` jacks, `data-port-id="clock"`, `data-port-type="gate"`):** every tempo source outputs one pulse per 16th note while it plays: the value goes to 1 at the step's (unswung) time and back to 0 half a step later (a `ConstantSourceNode` scheduled on the audio clock). Tempo followers measure the time between rising edges (crossing 0.5) to get seconds per 16th (BPM = 60 / (interval × 4)) and treat 3 s without a pulse as no clock. Sources: Metronome `CLOCK`, Drum Machine `CLOCK`, Sequencer `CLOCK`; followers: Stereo Delay `CLOCK`, Harmony Walker `CLOCK`, Chorale `CLOCK` (starts and stops with the source), Drum Machine `CLOCK IN` (`clock_in`), Sequencer `CLOCK IN` (`clock_in`), LFO `CLOCK` (with Sync on). Step followers (Drum Machine, Sequencer) move one step per pulse, start from their first step when the source starts and stop with it; their own Tempo and Play are set aside while a cable is in. **Sync API (2026-10-19, `clockSync.js`):** a new tempo source puts `ClockSource.attach(clockOutNode)` on its CLOCK output and calls `pulse(time, dur, first)` from its scheduler and `stop()` when it stops; a new follower uses a `ClockFollower` for its CLOCK input and calls `follower.cable(connected, source)` from `onInputConnected`; then any source and follower work together, sample-accurately, and plain gate signals work too (a few ms late). Any new tempo source must follow this, and add its `<type>:out:clock` key to the followers' `match` lists in `portGuide`.
- 🎹 **NOTES convention (note messages, not sound)**: a NOTES cable carries every held key. The source jack's node is a `PolyNoteBus` (`PolySynthModule.js`): `connect(sink)` / `disconnect(sink)` are called by `app.js` exactly like for an audio node (the sink is the target module's input object; a target without `noteOn` is ignored). On `connect` the sink gets `noteOn` for keys already held; `update(list, glide)` diffs the held keys (by MIDI note number, from `{ midiNote, freq }` items) and sends `noteOff(note)` / `noteOn(note, freq, glide)` (also when a held note's Hz changes; `glide` is the Keyboard's Slide time in seconds, 0 = off); `bend(amount)` (-1..+1) passes the Keyboard's pitch bend wheel to every sink that has a `bend` method (also sent on `connect`); `disconnect` sends `allNotesOff()`. The cable is drawn in the gate color (`data-port-type="gate"`). Sources: Keyboard `NOTES`, Harmony Walker `NOTES`; sinks: Poly Synth `NOTES`, Harmony Walker `FOLLOW`.
- **TIMBRE convention (fader settings, not sound)**: the source node is a `TimbreBus` (`TimbreModule.js`), `connect(sink)` / `disconnect(sink)` called by `app.js` like for an audio node (a sink without `setTimbreLevels` is ignored); `send()` calls `sink.setTimbreLevels(levels)` (array of 16 linear levels, partial 1 first; the Mixer uses as many as it has partials) on every sink. A sink may also have `attachBus(bus)` / `detachBus(bus)` (called on connect / disconnect) and `partialCount()`; the bus calls its `onChange` (the Timbre card's `drawBars`) on connect, disconnect and `changed()`. On `connect` it sends only when `synthApp.activeCable` is set, i.e. the user is dropping the cable right now; a cable restored by loading a patch or by Undo sends nothing, so faders moved by hand after a recipe keep their saved positions. Drawn blue (`signal: 'cv'`). Source: Timbre `TIMBRE`; sink: Mixer `TIMBRE`.
- 🔵 **Control Voltage / Modulation (`data-port-type="cv"` / `"fm"` / `"cutoff"`):** Blue (`#6366f1`). Continuous modulation voltages (e.g., Pitch CV, Envelope CV Out, LFO Out, Webcam CV Out).

### Standard Patching Flow
1. **Pitch / Gate**: Keyboard (`FREQ`) / Sequencer (`PITCH CV`) &rarr; VCO (`PITCH`) | Keyboard / Sequencer (`GATE`) &rarr; Envelope (`GATE IN`).
2. **Audio Path**: VCO (`AUDIO OUT`) &rarr; VCF (`AUDIO IN`) &rarr; VCA (`AUDIO IN`) &rarr; Output (`AUDIO IN`).
3. **Modulation Path**: Envelope (`CV OUT`) &rarr; VCA (`CV IN`) | LFO (`CV OUT`) &rarr; VCF (`CUTOFF CV`).

## 6. Web Audio Architecture & Audio Engine

- **Dynamic Hardware Sample Rate Detection**: Unconstrained `AudioContext` instantiation dynamically locks onto host interface sample rates (44.1kHz, 48kHz, 96kHz) without hardcoded assumptions, eliminating pitch and playback speed distortion.
- **AudioContext Lifecycle**: anything other than `running` / `closed` counts as asleep (`suspended`, and iPad Safari's `interrupted` after switching to another app). `audioEngine.wake()` resumes it; it runs on every `pointerdown` / `touchend` / `keydown` (capture phase, permanent) and when the page becomes visible again (`visibilitychange`, `pageshow`). If the sound is still off 700 ms after returning (Safari only restarts sound from a tap), and it had played before (`hasPlayed`, set from `statechange`), a toast says "Tap anywhere to turn the sound back on." `app.ensureAudioContextRunning()` uses the same rule. The Mic module (`watchMicInterruptions`) reconnects the microphone on return when its track ended while the page was hidden. **Sound output changes (iPad latency fix):** `getContext()` sets `navigator.audioSession.type = 'playback'` when Safari offers it (iOS 17+) and creates the context with `latencyHint: 'interactive'`. `audioEngine.outputStale` is set when the page is hidden, when the context reports `interrupted`, and on `navigator.mediaDevices` `devicechange` (headphones, Bluetooth). On the next `pointerdown` / `touchend` / `keydown`, `restartOutputIfStale()` rebuilds the system sound output with `ctx.suspend()` then `ctx.resume()`: it first fades the master out (`fadeOut(0.015)`), restarts 30 ms later and fades back in over 80 ms (`fadeInIfNeeded()`; if Safari refuses that resume outside the tap, the next tap's `wake()` starts the sound and `statechange` runs the fade-in), so the restart does not click (iPad could otherwise play notes up to a second late after such a change). `checkOutputRate()` (500 ms after returning to the page and after `devicechange`) opens a throwaway `AudioContext` to read the hardware sample rate and closes it; if it differs from the engine's `ctx.sampleRate`, the delay cannot be fixed in place, so it calls `window.showSoundRestartNotice()` (`pwa.js`, once per page load), which offers **Restart sound**: a reload that keeps the patch (`refreshKeepingPatch('sound')`, toast "Sound restarted. Your patch was kept; ..."). **Background on touch devices (iPad / iPhone):** because of the `'playback'` session, iOS would keep the patch sounding after the app is swiped away or closed (sequencers slower, with a lock-screen player). So when the page becomes hidden and `isTouchDevice()` (`(hover: none) and (pointer: coarse)`) is true, `sleepInBackground()` fades the master out (15 ms), sets `needsFadeIn` and 40 ms later (if still hidden) calls `ctx.suspend()` and sets `navigator.audioSession.type = 'auto'` (`sessionReleased`), which removes the lock-screen player. On return `cancelBackgroundSleep()` sets the type back to `'playback'` (or, if the page came back before the pause, cancels it and fades up); `wake()` resumes, and when the context reports `running` while `outputStale` is still set, `statechange` runs `restartOutputIfStale()` (faded suspend + resume, then fade in), because a plain resume after the background pause could leave iPad notes clearly late until the app was reopened. `restartOutputIfStale()` keeps `outputStale` set while the context is not running, so this rebuild also follows an `interrupted` return. Desktop is unchanged: a background tab keeps playing.
- **Master chain & click-free clearing**: `audioEngine.setupMasterProtection()` builds `dcBlocker` (20 Hz high-pass, the input every Output module connects to via `getMasterInput()`) → `masterLimiter` (brickwall compressor) → `masterFade` (gain, normally 1) → `ctx.destination`. `audioEngine.fadeOut(seconds)` ramps `masterFade` linearly to 0 and returns the audio time it is silent. `audioEngine.fadeAround(fn)` fades out over 80 ms, then waits (polling every 15 ms, at most 600 ms) until `ctx.currentTime` is 30 ms past that point, because iPad renders audio ahead in bigger chunks and timers can be late, so a fixed timer could tear modules down before the silence was really rendered; then it runs `fn` and ramps back to 1 over 80 ms starting 20 ms later (when the context is not running it just runs `fn`). **Leaving the page** (`fadeOnLeave()`, set up in the constructor): `beforeunload` and `pagehide` start a 15 ms fade-out so closing the window or reloading does not click (`pageshow` with `persisted` brings it back up); the update / Restart sound reload in `pwa.js` (`refreshKeepingPatch`) fades out over 80 ms and reloads 130 ms later. `app.withAudioFade(fn)` uses it whenever the canvas has modules; the **Clear** button (`clearWorkspace`) and **Load** (`importPatch` → `loadPatchData`) run through it, so cutting every sounding module at once no longer clicks. Deleting modules by hand (a module's × button, or Delete / Backspace on selected modules) goes through `app.removeModules(ids)`, which runs `deleteNode` behind the same fade; `createModule` removes the modules' inline `onclick="synthApp.deleteNode(...)"` from the × button so only the faded path runs. `deleteNode` itself stays immediate (used by Clear, Undo / Redo and patch loading). A new Output module starts its `volumeGain` at 0 and rises to its volume (`setTargetAtTime`, 15 ms), so presets and new patches also start without a click.
- **Connection Mechanics & Auto-Alignment**: Cables rendered on canvas as dynamic Bezier paths connecting source output ports to target input ports/AudioParams. Automatically updated in real time via `ResizeObserver` whenever module card geometry or internal UI elements undergo layout shifts.
- **Input notifications**: after `connectAudio()` connects a cable, and after `disconnectAudio()` removes one, `app.js` calls `notifyInputConnection()`, which calls the target module's optional `onInputConnected(portKey, connected, source)` (portKey = `data-port-id` || `data-port-name` || `data-port-type`; source = the output node the cable comes from, so a CLOCK input can find that node's `clockSource`, see `clockSync.js`). The Oscillator uses it for PITCH.
- **Module creation order** (`createModule`): build the card, `bindEvents`, attach drag and port events, append the card to the page, then `setState(state)`, so modules that look up their own controls with `document.getElementById` also update their sliders and labels.
- **CV scales are not uniform** (know this when writing presets): Envelope ENV OUT 0..1; Keyboard/Sequencer gate 0/1; Keyboard FREQ and Sequencer PITCH in Hz; LFO OUT ±(depth% × 2) i.e. depth 50 = ±100; Webcam X/Y 0..cvDepth (1000) and MOTION 0..1. Filter CUT MOD multiplies its input by Mod Depth (Hz), so an LFO into the filter needs a small LFO depth (e.g. depth 1 with Mod Depth 300 = ±600 Hz).
- **Safe Routing Protocol**: Patch cable creation uses `getNodeOrParamForPort()` wrapped in `try/catch` blocks to safely handle audio-to-audio node connections and audio-to-AudioParam CV modulation.

## 7. Patch Persistence & Module Protocol (JSON Schema)

### Saving and loading files
- **Save** (`exportPatch()` in `app.js`) gets the patch object below from `getPatchObject()` and turns it into a `Blob` (`application/json`) named `synth_patch_<timestamp>.json`. Patches are not stored inside the site; they are always a file.
- **On iPad / iPhone** (user agent `iPad|iPhone|iPod`, or `MacIntel` with `maxTouchPoints > 1` for iPadOS) and when `navigator.canShare({ files })` is true, Save opens the system share sheet (`navigator.share`) so the user picks **Save to Files** (or AirDrop, Mail, etc.). Cancelling the sheet does nothing; any other share error falls back to the download below.
- **Everywhere else** `downloadBlob()` downloads the file through a temporary object URL (revoked after 10 s) and shows the toast `Patch saved as <name> (in your Downloads folder).`
- **Load** opens the hidden `#import-patch-input` (`accept=".json,application/json"`), reads the file with `FileReader`, and passes it to `loadPatchData()`.

## 8. Repository, Deployment & Working Rules

- **Source of truth:** GitHub repository `noambartov/sound-playground`, branch `main`. Older local copies (e.g. the iCloud folder `sound playground v_4`) are not updated automatically.
- **Live site:** GitHub Pages, deployed from `main` / root. URL: https://noambartov.github.io/sound-playground/. Every push to `main` redeploys automatically.
- **No build step:** plain static files; `index.html` is the entry point.
- **Repo housekeeping files:** `README.md` (short description), `.gitignore` (ignores macOS `.DS_Store`), `CLAUDE.md` (working rules for Claude sessions, including that deploys need no PWA cache bump), `LICENSE` ("Copyright (c) 2026 noam bartov. All rights reserved.": the code is publicly visible but no license is granted; copying, modifying, distributing or using any part needs written permission; the repo stays public because GitHub Pages on a free account needs it), `ROADMAP.md` (the owner's backlog of future ideas plus a market review; ideas there are not built until the owner approves, and new ideas from any thread are added there).
- **Publish rule:** every finished change is merged into `main` right away, without waiting for the owner to ask, because the live site is the owner's only way to see changes. Test in a headless browser first. After merging, wait until the `pages build and deployment` GitHub Actions run whose `head_sha` matches the merge commit reports `completed` / `success` (e.g. `https://api.github.com/repos/noambartov/sound-playground/actions/runs?per_page=1`), and only then tell the owner the site is ready (usually 1-2 minutes). After a deploy, a hard refresh (Cmd+Shift+R) may be needed in a browser tab; the installed iPad app shows its own "new version" notice instead; the `?v=` numbers on `styles.css` / `app.js` in `index.html` must be bumped on every change to those files so browsers fetch the new version.
- **Installable app (PWA):** the site can be added to the iPad home screen (Safari: Share > Add to Home Screen) and then opens full screen in its own window and works offline.
  - `index.html` `<head>`: `<link rel="manifest" href="manifest.webmanifest">`, `theme-color` `#0f172a`, `mobile-web-app-capable` and `apple-mobile-web-app-capable` `yes`, `apple-mobile-web-app-title` "Sound Playground", `apple-mobile-web-app-status-bar-style` `default`, `apple-touch-icon` `icons/icon-180.png`, `icon` `icons/icon-192.png`. `pwa.js?v=1` is the last script.
  - `manifest.webmanifest`: name / short_name "Sound Playground", `start_url` and `scope` `./` (works under the `/sound-playground/` Pages path), `display: standalone`, `orientation: any`, background and theme `#0f172a`, icons 192 and 512.
  - `icons/icon-180.png`, `icon-192.png`, `icon-512.png`: full-bleed square (iOS rounds the corners), background `#0f172a`; a thick sky-blue (`#38bdf8`) sine wave, 1.5 cycles, across the upper half with round ends; below it two jacks (light `#e2e8f0` rings with a `#334155` center) joined by a sagging amber (`#f59e0b`) cable. Drawn at 1024 px with Pillow (circles stamped along each path) and downscaled.
  - `sw.js` (service worker, cache `sound-playground`). **Zero maintenance: no version number or file list to update when the site changes.** The file list is read live from `index.html`: every `src="..."` / `href="..."` without `:` or `#`, plus any `addModule('...')` path found in those scripts (worklets like `delay-worklet.js`). Install: caches all of them, `skipWaiting()`; activate: `clients.claim()`. Fetch (same-origin GET, never `sw.js` itself): **network first** with `cache: 'no-cache'` (so online always gets the latest deploy), the response is stored (older copies of the same path with another `?v=` are deleted); page navigations always fetch and store `./` (index), and a redirected page answer is re-wrapped because Safari refuses redirected responses from a service worker. If the network fails, or gives nothing for 4 s, the stored copy is served (`ignoreSearch` fallback, so a bumped `?v=` still finds the old file offline). Message `check-update`: re-fetches the whole list, compares each file's bytes with the stored copy, stores what changed, and if anything changed posts `update-available` back to the page.
  - `pwa.js`: registers `sw.js` (only on http/https). Asks the service worker `check-update` 15 s after load, every 10 minutes, and whenever the app comes back to the foreground (`visibilitychange`), at most once a minute; nothing is checked once the notice is showing. On `update-available` it shows the notice (section 3.6). **Refresh** keeps the work: if there are modules it stores `synthApp.getPatchObject()` (the same object Save writes, from `app.js`) in `sessionStorage` key `sp_carry_patch`, then reloads; on `load` the patch is restored with `loadPatchData` (Output volume starts at 0 as for every load) and the toast says "Updated to the new version. Your patch was kept; raise Master Volume on the Output module to hear it." Exposes `window.showUpdateNotice()` for testing.
  - Result for deploys: the installed app picks up every push to `main` by itself; an app left open shows the notice within ~10 minutes or the next time it is brought to the front, and a fresh launch loads the new version directly. In a normal browser tab the same service worker makes a plain refresh load the latest files.
- **Documentation rule:** every change to a file or to a foundational setting must be reflected in this `architecture.md` in the same commit, so that this document always holds everything needed to rebuild the site from scratch.
