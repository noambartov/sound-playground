# Modular Synthesizer Sandbox - Architecture & Specification (v_5)

## 1. Overview
A browser-based, interactive modular synthesizer sandbox built with pure HTML5, CSS3, ES6 JavaScript, and the Web Audio API. Designed with a modular Eurorack-inspired workflow, clean visual aesthetic, responsive canvas routing, and support for audio processing, control voltage (CV) routing, and experimental modulation sources (such as Granular synthesis and Webcam tracking).

---

## 2. File Hierarchy & Roles

### Core Application & UI Logic
- **`index.html`**: Main entry point. Houses the DOM skeleton including the categorized floating Sidebar, Toolbar (a `Move` drag handle, Undo `#undo-btn` (&#8630;) and Redo `#redo-btn` (&#8631;) arrow buttons, Help, Theme toggle, Presentation Mode, `Cables: Front/Back` toggle `#cable-layer-btn`, Zoom, Save/Load, Clear, Tooltips), Canvas Viewport overlay (`#connections-canvas`), Help & Presets Modal (`#help-modal`), and scripts loading order.
- **`styles.css`**: Complete application design system using CSS Custom Properties (`:root` / `.dark-theme`). Defines Clean White & Dark theme colors, module card layouts, wide granular card layouts, VU meter animations, cable canvas positioning (`#connections-canvas` `z-index: 30`, above `#workspace-viewport` `z-index: 1`; `body.cables-behind` drops the canvas to `z-index: 0` so cables go behind the modules), draggable panel handles (`.panel-drag-handle`, `.panel-dragging`), custom scrollbars, and modal layouts. Toolbar buttons that are `:disabled` (e.g. Undo with nothing to undo) are faded to 35% opacity. `index.html` loads it as `styles.css?v=3.3` and `app.js?v=12` (bump the `?v=` number on each change to defeat browser caching).
- **`app.js` (`SoundSandboxApp`)**: Main controller class managing:
  - Global application state, module registry, and viewport Zoom/Pan (`Cmd`/`Ctrl` + Left-Click drag).
  - Web Audio Context initialization and user interaction audio unlock.
  - **Dynamic Cable Redrawing & `ResizeObserver` Integration:** Automated observation of DOM element size changes inside module cards (e.g., dynamically showing/hiding sliders like Pulse Width). Triggers immediate cable repositioning and canvas redraws (`drawConnections()`), alongside manual control via `updateCables()`.
  - **Template modules first:** `createModule()` first asks `ModuleBase.get(type)` (see `ModuleBase.js`); only if no template module is registered for that type does it fall through to the hand-written `if / else if` list of the original modules.
  - **Robust Instantiation & Webcam Fallback:** Enhanced type alias mapping (supporting `webcam`, `webcam_controller`, `webcam-controller`, `camera`) and graceful fallbacks/alerts if required module scripts are unmapped or missing.
  - Interactive cable connection drawing (dynamic Bezier curves color-coded by port type) on `#connections-canvas`.
  - **Port lookup (`getPortElement(card, isOutput, info)`)**: searches only the ports of the requested direction (`.port-out`/`.output-port` or `.port-in`/`.input-port`), matching `info.channel` (`data-channel`) first, then `info.id || info.name || info.type` against `data-port-id`, then `data-port-name`, then `data-port-type`; falls back to the first port of that direction. When a port is pressed, the cable already plugged into it is found by comparing `getPortElement(...)` with the pressed element itself, never by port type alone (otherwise a free port of the same type, e.g. Keyboard `bend`, would pull out the `freq` cable).
  - **Multiple cables from one output (fan-out)**: dragging from an output port always starts a new cable, so one output can feed several inputs (e.g. both stereo inputs). `Shift`+drag from an output pulls out the most recently connected cable at that output (its input end stays put) so the source end can be moved. Dragging from an input port pulls out the cable plugged into it (inputs hold one cable each from the user's point of view). Dropping a cable that already exists (same output port to same input port) adds nothing.
  - **Port colors**: `updatePortConnectedClasses()` adds `.connected` to both ends of every cable and sets the CSS variable `--cable-color` on the port to that cable's color (`getConnectionColor()`); CSS paints the port and a ring in that color, so it is visible where each cable plugs in even with `Cables: Back`. Cable color is `getCableColor(portType, connId)` where `connId` combines both modules and both ports (`channel || id || name || type`), so two cables between the same two modules get different shades.
  - **Cable selection & deletion**: `drawConnections()` stores each drawn cable's Bezier points in `cableHitPaths`. A left click on the empty workspace runs `findCableAt(x, y)` (40-sample Bezier hit test, 8 px tolerance, topmost cable wins). First click selects (`selectedConnection`, drawn 6 px wide with a halo), a second click on the selected cable or `Delete`/`Backspace` deletes it (`deleteConnection()`), `Escape` or a click elsewhere deselects. Clicks inside a module card never reach cables, so moving a slider can never touch a cable.
  - **Cable layer toggle (`toggleCableLayer()`)**: `Cables: Front` (default, cables over modules) or `Cables: Back` (button highlighted, `body.cables-behind`). Remembered in `localStorage` key `sp_cables_behind`.
  - **Draggable panels (`initDraggablePanels()`)**: the Sidebar is dragged by its `Modules` title (`.sidebar h3`), the Toolbar by its `Move` label (`.toolbar .panel-drag-handle`). Positions are clamped to the window, saved in `localStorage` (`sp_panel_sidebar`, `sp_panel_toolbar`), and reset by double-clicking the handle. All `localStorage` access is wrapped in `try/catch`.
  - **Collapsible Sidebar categories (`initSidebarGroups()`)**: each `.sidebar-group-title` is a framed, clickable row (`role="button"`, focusable, Enter/Space also toggle, `aria-expanded`) that opens or closes its group by toggling `.collapsed` on the `.sidebar-group` (CSS hides `.add-module-btn` children of a collapsed group). The title shows the number of modules in the group on the right (`data-count`, drawn by CSS `::after`, so the title's `textContent` stays the group name that `ModuleBase` matches); an open group's title is in the primary color. All groups start closed; the names of open groups are remembered in `localStorage` `sp_sidebar_open`. A delegated click handler on the Sidebar plus a `MutationObserver` keep this working for groups and buttons that `ModuleBase.register()` adds later. Text only, no arrow icons (design rule 3).
  - **Sidebar search (`#sidebar-search`)**: an `input type="search"` (placeholder `Search modules`) under the `Modules` title, handled in `initSidebarGroups()`. While it has text the Sidebar gets `.searching`: each `.add-module-btn` whose label or `data-type` contains the text (case-insensitive), or every button of a group whose title contains it, is shown even inside a closed category; the other buttons get `.search-hidden` and groups with no match `.search-empty` (both hidden); `p.sidebar-no-results` (`No modules found`) shows when nothing matches. Clearing the box restores the open/closed categories as they were. Enter adds the first match, Escape clears the box. Its `keydown` / `keyup` are stopped so typing does not play the Keyboard module or trigger app shortcuts. The `MutationObserver` re-runs the filter when template modules add buttons.
  - **Undo / Redo history (`initHistory()`)**: every history entry is a snapshot string from `takeSnapshot()` (modules sorted by id with `id`, `type`, `x`, `y`, `getState()`, plus all cables). `scheduleHistoryCapture()` runs 250 ms after any `pointerup`/`pointercancel`, `change` event, `keyup`, `deleteNode()`, `deleteConnection()` or a finished `loadPatchData()`; `captureHistory()` skips identical snapshots and waits while a pointer is still down or a cable is being dragged. Up to 100 steps (`undoStack`, `redoStack`; any new action clears redo). `restoreSnapshot()` changes only what differs: deletes extra modules, moves cards, calls `setState()` on modules whose state changed (rebuilding a module if `setState` cannot reach the old state, e.g. a removed mixer channel), creates missing modules with their original ids, then removes/adds cables so `this.connections` matches the snapshot (`connectionKey()` = both modules + `channel ?? id ?? name ?? type` of both ports). Shortcuts: `Cmd/Ctrl+Z` undo, `Cmd/Ctrl+Shift+Z` or `Cmd/Ctrl+Y` redo (ignored while typing in a text/number field). Theme, zoom/pan and selection are not part of the history. Because snapshots are compared as text, `getState()` must return the intended values the module stored itself, never a live `AudioParam.value` (which lags behind ramps); Output (`this.volume`), VCA (`this.gainValue`) and Filter (`this.resonance`) follow this.
  - Module lifecycle (spawning, dragging, selecting, deletion with `unobserve`, clear canvas).
  - Presentation / Play Mode toggling (`isPresentationMode`).
  - Global tooltips state management (`toggleTooltips()`).
  - Module placement: a module added from the Sidebar is placed by `findFreeSpawnPoint()` at the first spot (scanning the free screen area left-to-right, top-to-bottom in 30 px steps) that is not under the Sidebar/Toolbar (`getFreeViewRect()`, works wherever those panels were dragged) and keeps 24 px from every other card; if the screen is full it goes to the right of all modules and the view pans to show it.
  - `fitToModules(onlyIds)`: after any patch load, zooms (0.4 to 1) and pans so all modules (or only the given ids: the modules of a preset just added) fit in the free screen area.
  - `loadPatchData(patch, opts)`: without options (the Load button) it clears the workspace and recreates the patch with its own ids, positions and theme. With `{ add: true }` (presets from the manual) on a non-empty canvas it keeps everything, ignores the patch theme, gives each new module a fresh id (`<type>_<time>_<random>`) and remaps the cables to them (a slider-cable `knob` ref ending in the old module id is rewritten too), and shifts the patch so its left edge is 120 px right of the existing modules and its top matches theirs. It returns the ids of the modules it created.
- **`audioEngine.js`**: Centralized Web Audio engine wrapper. Standardizes `AudioContext` management, master input/output node routing, global volume control, and dynamic hardware sample rate detection.
- **`PatchManager.js`**: Handles JSON serialization and deserialization of synthesizer patches (saving canvas layouts, module parameters, active settings, and cable wire connections). **Note:** this file is currently *not* loaded by `index.html`; the live save/load logic is `exportPatch()` / `loadPatchData()` inside `app.js`.
- **`portGuide.js`**: Jack hints. Holds `GUIDE`, the single table of every jack (key `<moduleType>:<in|out>:<portKey>`, where portKey is `data-port-id` || `data-port-name` || `data-port-type` || `default`, mixer channel numbers dropped) with its name, signal kind, a one-line explanation, where to connect it from/to, and a `match` list of recommended partner jacks. Shows a themed `.port-hint` card 250 ms after the pointer rests on a jack (replaces the native `title`, follows the Tooltips ON/OFF button via `body.tooltips-disabled`). While a cable is dragged (reads `synthApp.activeCable` on capture-phase pointerdown) it adds `body.cable-dragging` and marks every jack: `.port-suggested` (recommended partner, pulsing primary ring), `.port-compatible` (opposite direction on another module), `.port-incompatible` (faded). Always-visible labels: while Tooltips is ON (and not in Play Mode or with Help open) every jack gets a small tag under it in `#port-chip-layer` (a fixed layer, z-index 90, above the canvas and below the Sidebar/Toolbar, because cards clip their contents): `IN`/`OUT` (inputs outlined, outputs filled in the primary color), the signal kind, and a `from …` / `to …` hint from the `CHIPS` table. A `requestAnimationFrame` loop repositions the tags only when a jack moved or the module stacking order changed (signature of rounded jack positions plus each card's `z-index`); a jack covered by another module or a menu (`document.elementFromPoint` at its center is not inside its own card) gets no tag, so tags never show through a module; a tag shrinks to `compact` (`IN · CV`) and then `tiny` (`IN`) while it overlaps another tag or covers another jack. On touch screens (no hover) pressing a jack shows the full hint card until the finger lifts. Exposes `window.portGuide`. Every new module/jack must get a `GUIDE` and a `CHIPS` entry.
- **`ModuleBase.js`** (loaded after all hand-written module scripts, before the template modules and `modulation.js`): the shared template for new modules, exposed as `window.ModuleBase`. **Every new module should be built on it.** A module is a class `extends ModuleBase` with a `static def` and a final `ModuleBase.register(TheClass)` call. `register()` stores the class in `ModuleBase.registry` (by `def.type` and `def.aliases`), adds a `.add-module-btn` to the Sidebar group whose title equals `def.menu.group` (creates the group at the end if missing; the Sidebar uses a delegated click handler so injected buttons work), and adds each jack's `guide` / `chip` to `portGuide.GUIDE` / `CHIPS` (key `<type>:<in|out>:<jack id>`, `name` and `signal` filled in from the jack). `def` fields: `type`, `title` (card header), `width` (px, default 220), `menu: { group, label }`, `aliases`, `params` (controls, in display order), `inputs` and `outputs` (jacks). A param is `{ id, label, value, kind }`: default kind is a slider (`min`, `max`, `step`, `unit` or `format(v)` for the readout); `kind: 'select'` with `options: [[value, label], ...]`; `kind: 'toggle'`, an `.action-btn.module-toggle` reading `<label>: On/Off` (`.active` when on; consecutive toggles share one `.module-toggle-row`). A jack is `{ id, label, signal: 'audio' | 'cv' | 'gate', title, guide: { text, to | from, match }, chip }`; it renders as `.port` with `data-port-id="<id>"` and `data-port-type="<signal>"`; jack ids must be unique across inputs and outputs. A jack marked `inline: true` is left out of the bottom ports row; the module draws it itself with `renderPort(jack, 'in' | 'out')` inside `renderBody()` (e.g. the Drum Machine's per-row jacks), and it still gets its jack hint. Rendering: `.node-header` (title + `.delete-module-btn` `×`, which `app.js` binds), `.node-body.module-base-body`, then `renderBody()` (custom HTML), the controls, and `.ports-row.module-base-ports` (inputs first, docked at the bottom). Element ids are `<type>_<name>_<module id>` (`elId(name)`, `el(name)`): sliders `<type>_p_<param>_<id>`, readouts `<type>_v_<param>_<id>`, so every slider is a stable target for LFO / Ribbon slider modulation with no extra code. The template provides `getState()` (all params plus `getExtraState()`), `setState()` (updates values, widgets and readouts, then `setExtraState()`), `setParam(id, value)` (clamps, stores, calls `onParamChange`, updates the UI; slider `input` events from modulation go through it), `getNodeOrParamForPort(jackId)` (returns `outputNodes[id]` or `inputNodes[id]`, used by `app.js` for both directions), `makeConstant(value)` (a started `ConstantSourceNode` for CV / gate outputs) and `own(node)` (both are stopped and disconnected by `cleanup()`). Subclass hooks: `build()` (create audio nodes and fill `inputNodes` / `outputNodes`; it runs inside the base constructor, so subclasses set their fields there and do not use class field initializers or their own constructor), `onParamChange(id, value)` (called once per param right after `build()`, then on every change), `renderBody()`, `onMount(card)`, `getExtraState()` / `setExtraState(state)`, `destroy()`. Adding a module = one new file + one `<script>` tag in `index.html` (after `ModuleBase.js`) + a row in the Module Type IDs table and a file entry here + a `helpData.js` `modules` entry (English and Hebrew), Hebrew `ports` entries and a `demo-<module>` preset for the manual; `app.js`, `portGuide.js` and `help.js` need no changes. Design rules (section 3) still apply: English text only, no icons.
- **`modulation.js`** (loaded right before `app.js`): `KnobModulation`, "LFO to any slider". A cable from LFO OUT dropped on any `input[type="range"]` of another module is stored as a normal entry in `app.connections` with `toPortInfo: { id: 'knob:<ref>', knob: '<ref>' }`, where `<ref>` is `#<slider id>` or `i<index among the card's sliders>` (`refFor()` / `resolve()`). `app.js` creates `this.knobMod`; `connectAudio` / `disconnectAudio` call `knobMod.add()` / `remove()` for such cables instead of Web Audio connections; `getPortElement(card, false, info)` returns the slider for `info.knob`, so drawing, deleting, undo and saving reuse the normal cable code; `getPortCenter()` ends such a cable at the slider's left end. Every animation frame the loop reads each source LFO's `getKnobModValue()` (raw wave -1..1 from an `AnalyserNode` tap × Depth%) and sets the slider to `base + sum of offsets × (max - min) / 2` (clamped), then fires an `input` event, so each module reacts through its own slider code (no per-module changes; ~60 updates per second, so very fast LFO rates step). The base is what the user set: if the slider's value differs from the last value the loop wrote (user drag, undo, `setState`), that becomes the new base. `withBaseValues(fn)` puts every modulated slider at its base while `fn` runs (used by `takeSnapshot()` and Save, so history and saved files hold the user's values; the modulated value is written back in the same task). A `.knob-mod-band` strip (cable color) under the slider shows how far it moves (base ± Depth × half the range). Removing the cable (click it twice, delete either module, undo) puts the slider back at its base. Only modules with `getKnobModValue()` (the LFO, the Ribbon) can modulate sliders; the loop calls `getKnobModValue(conn.fromPortInfo)`, so a module with several outputs answers per jack (the LFO ignores the argument); `Shift`+drag from LFO OUT skips slider cables. **Plugging in (API for new modules):** a control is modulatable automatically when it is an `input[type="range"]` inside the module card with a stable `id` (include the module id) whose `input` listener applies the value; nothing else is needed. A new modulation source only needs `getKnobModValue(fromPortInfo)` (current offset, -1..1, already scaled by its depth) and `getKnobModDepth()` (0..1, for the range strip) on its instance.
- **`help.js`**: the manual ("book") in `#help-modal`. Opens from `#help-btn`, closes with `×`, a backdrop click or Escape. English by default (`currentLang = 'en'`); the `#help-lang-toggle` button ("Hebrew" / "English") switches to Hebrew and sets `dir="rtl"` on the modal. Six tabs built from `helpData[lang].tabs` as `.book-tab` pills: **Start here** (`start`), **Modules** (`modules`), **Recipes** (`recipes`), **Signals** (`basics`), **Troubleshooting** (`trouble`), **Shortcuts** (`shortcuts`); the four text tabs show `sections[tab]` (HTML made of `.help-card` blocks). Modules tab: a grouped list on the side (`.book-mod-list`, groups in the order sources, controllers, processors, modulation, output, other, titled by `ui.groups`; on screens under 720 px it becomes a wrap of buttons above the panel) and a detail panel for the selected module: name, a "Load the demo patch" `.preset-btn` (when `preset` exists in `presetData`), summary, Controls, Inputs and Outputs tables, Tips. **The jack tables are not written in helpData**: they are generated from `window.portGuide.GUIDE` (every key starting `<type>:in:` / `<type>:out:`, so template modules' jacks appear automatically): jack name, a signal tag (`.tag-audio` / `.tag-cv` / `.tag-gate`), the explanation and "Connect from / to"; in Hebrew the text and the where-line come from `helpData.he.ports[key]` (`{ text, where }`), falling back to English. **Fallback for a module without an entry**: every Sidebar `.add-module-btn[data-type]` without a `modules` entry is still listed, in the group matching its Sidebar group title (`SIDEBAR_GROUPS`), with its jack tables only; there is no separate "New modules" section, because every module must get a written entry (see `helpData.js`). When several jacks of a module share a label (the Drum Machine's IN / OUT / TRIG per row), the table shows each jack's `title` (stored in `GUIDE` by `ModuleBase.addPortGuide`) instead. Recipes tab: a card per `recipes` entry (title, What you learn, How to play steps, "Load this patch"). Search (`#help-search-input`): while it has text, the tabs are unselected and the content shows every matching card from all tabs (text-tab cards, module summaries with a button that opens the module in the Modules tab, recipe cards), each labeled with its tab, or `ui.noResults`. Loading a preset calls `synthApp.loadPatchData(preset, { add: true })`, so the preset is **added** next to the modules already on the canvas (nothing is removed; Undo takes it back), resumes the audio context, after 300 ms starts the preset's own Sequencers (`togglePlay()`) and template modules that have a `start()` method and are not `playing` (Drum Machine, Metronome), only those whose ids `loadPatchData` returned, and closes the manual; the "patch loaded" notice and the fit to view come from `app.js`. Styles are injected once (`#help-custom-css`) and use the theme variables (`--panel-bg`, `--subtle-bg`, `--text-color`, `--panel-border`, `--btn-*`, `--primary-color`, `--muted-text`), so the manual follows light / dark theme; `.chip-demo.chip-in` / `.chip-out` copy the jack label look for the text.
- **`helpData.js`**: content only. `window.helpData = { en, he }`, both with the same shape: `title`, `searchPlaceholder`, `tabs` (the six tab names), `ui` (labels: inputs, outputs, controls, tips, none, from, to, tryIt, loadRecipe, youLearn, howToPlay, noResults, groups), `sections` (`start`, `basics`, `trouble`, `shortcuts` HTML), `modules` (one entry per module, in list order: `{ type, group, name, preset, summary, controls[], tips[] }`; `name` stays English in both languages because it matches the UI), `recipes` (`{ preset, title, learn, steps[] }`; currently classic-mono, seq-groove, ambient-drone, ext-processing, demo-reverb, demo-envelope, demo-lfo, demo-mixer), and in `he` only `ports` (Hebrew `{ text, where }` per `portGuide` key). Then `window.presetData` (section 7). **Every new module needs, in the same change that adds it,** a `modules` entry in both `en` and `he` (placed in its group among the existing modules), Hebrew `ports` entries for its jacks, and a demo preset `demo-<module>` in `presetData` named in the entry's `preset`, so its manual page has a "Load the demo patch" button.

- **`pwa.js`** (loaded last, after `app.js`), **`sw.js`**, **`manifest.webmanifest`**, **`icons/`**: the installable app (PWA). See section 8, "Installable app (PWA)".

### Audio Processing & Generation Modules
- **`OscillatorModule.js` (VCO)**: Primary sound source (`OscillatorNode`). Features waveform selection (sawtooth, square, triangle, sine), pitch tuning, fine tune, octave controls, pulse width modulation, a `PITCH` input (`data-port-type="pitch"`, a GainNode into `frequency`) and an `FM IN` input (straight into `frequency`). While at least one cable is plugged into PITCH (`onInputConnected('pitch', true)` counts them), the base frequency is held at 0 so the incoming Hz value (Keyboard FREQ, Sequencer PITCH CV) plays exactly in tune, the Frequency slider is disabled and its label reads `from PITCH IN`; unplugging restores the slider value. FM IN adds to the current pitch (vibrato, FM). The Frequency slider runs 0 to 1 (step 0.001) and maps to 20 to 4000 Hz through `OscillatorModule.sliderToFreq` / `freqToSlider`: `freq = 20 * 200^(pos^k)`, with `k` chosen so the midpoint (0.5) reads 200 Hz. The patch JSON stores the frequency in Hz, not the slider position.
- **`AudioInputModule.js`**: Real-time microphone/external audio input capture via `getUserMedia`. Includes input Gain control, ON/OFF toggle, and a live VU meter for visual feedback.
- **`FilterModule.js` (VCF)**: Frequency filter (`BiquadFilterNode`). Lowpass/Highpass/Bandpass modes, Cutoff frequency slider (0 to 1, step 0.001, mapped to 20 Hz to 15 kHz by `sliderToFreq` / `freqToSlider`: `freq = 20 * 750^(pos^k)`, with `k` chosen so the midpoint (0.5) reads 700 Hz, which is also the default cutoff; the patch JSON stores Hz), Resonance (Q), and `Cutoff CV` modulation input port.
- **`EnvelopeModule.js` (EG)**: ADSR Envelope Generator. Controls: Attack, Decay, Sustain, Release, manual Trigger button, Gain shaping, and CV voltage generator for external parameter modulation.
- **`VcaModule.js` (VCA)**: Voltage Controlled Amplifier. Amplitude modulation control. Default gain starts at 0.0 to prevent audio leakage until triggered by CV. Ports: Audio `IN`, Audio `OUT`, and `CV` input. CV IN goes through a WaveShaper clamp (curve `[-1, 1]`) before the gain param, so any modulator can move the gain by at most ±1 (an Envelope 0..1 passes unchanged; an LFO, whose output is sized in Hz, cannot blow the volume up). A Gate (0/1) straight into CV gives simple on/off notes.
- **`LfoModule.js` (LFO)**: Low Frequency Oscillator, standard 220 px card titled `LFO`, laid out like the other modules (one column): a theme-aware wave preview canvas (`.lfo-preview`: the selected wave shape in `--muted-text`, its height following Depth, and a `--primary-color` dot on the right riding the live LFO value, redrawn every frame by `startPreviewLoop()` until `cleanup()`), Waveform menu, Rate (0.1-20 Hz, log slider) and Depth (%) sliders with readouts, a `Reset Phase` `.action-btn`, and ports `RATE IN` / `OUT`. An `AnalyserNode` (`fftSize` 32) taps the raw oscillator for the preview dot and for `getKnobModValue()` / `getKnobModDepth()` (slider modulation, see `modulation.js`). Its OUT cable can go to a CV jack or be dropped on any slider of another module.
- **`MixerModule.js`**: Multi-channel audio summing mixer. Dynamic channel gain, per-channel Stereo Panning (`StereoPannerNode`), mute/solo controls, master level control, and split `OUT L` / `OUT R` output ports.
- **`ReverbModule.js`**: Algorithmic / Impulse Response Reverb effect processor. Controls for Mix (Dry/Wet), Decay Time, Pre-delay, and Tone filter.
- **`GranularModule.js`**: Advanced Granular Synthesis engine. Real-time grain extraction from loaded audio files. Controls for Grain Size, Density, Pitch, Spray (Jitter), Grain Pan, and dual assignable CV modulation inputs (`cv1`, `cv2`). Default source mode `live`: IN L/R are recorded into a 5 s ring buffer every 15 ms; each tick copies exactly the samples that arrived since the previous tick (the newest part of the 2048-sample analyser window), so the buffer is continuous. Without an input it is silent. `density` is grains per second (integer).
- **`DegraderModule.js`** (template module, type `degrader`, Sidebar group Processors & Effects, 220 px card): a one-knob lo-fi effect, mono. Jacks: audio `IN` (`inNode`, a GainNode) and audio `OUT` (`outNode`). One slider `Degrade` (`amount`, 0-100%, default 50; readout `<n>% <stage>` with stage `Clean` (0), `Tape` (<30), `Lo-Fi` (<60), `Wrecked`). All processing is one AudioWorklet `degrader-processor`, loaded once from a string through a Blob URL (`DegraderModule.loadWorklet`, a shared promise); until it is ready (or if AudioWorklet is missing) `IN` is wired straight to `OUT`. The node has `channelCount: 1` (`explicit`, stereo is downmixed) and a k-rate `amount` param (0..1) set with `setTargetAtTime(…, 0.02)` from `onParamChange`, so LFO / Ribbon slider cables move it smoothly. Per sample, in order: tape wobble (a 4096-sample delay line, 6 ms base plus wow 0.7 Hz up to 2.5 ms and flutter 7 Hz up to 0.3 ms, scaled by `0.6·seg(30-60%) + 0.4·seg(60-100%)`, linear interpolation); saturation `tanh(1.5·drive·x)/tanh(1.5·drive)` blended in over 0-30% with drive 1 → 4 over 30-100%; sample-rate reduction by sample-and-hold (none below 30%, the context rate → 8 kHz over 30-60%, 8 kHz → 1.5 kHz over 60-100%, exponential); bit reduction `round(x·2^(bits-1))/2^(bits-1)` (none below 30%, 16 → 8 bits over 30-60%, 8 → 3 over 60-100%, continuous); from 60% hiss (lightly filtered white noise, up to 0.02) and record crackle (random clicks up to 30 per second, amplitude 0.05-0.35, decaying ×0.55 per sample), both scaled by `seg(60-100%)` and present even with no input; two cascaded one-pole low-passes (open at 0%, 20 kHz → 8 kHz over 0-30%, 8 → 4 kHz over 30-60%, 4 → 1.5 kHz over 60-100%); output gain 1 → 0.7 over 30-100%. `seg(lo-hi)` is the knob's position inside that range, 0..1.
- **`WavetableModule.js`** (template module, type `wavetable`, Sidebar group Sound Sources, 260 px card): a wavetable oscillator, mono. **Jacks**: `PITCH` (cv, a note in Hz; while it has a cable, counted by `onInputConnected`, the base frequency is 0 and the Frequency readout says `from PITCH IN`, slider disabled), `FM` (cv, Hz added after Octave / Tune), `POS` (cv, through a GainNode `posIn` whose gain is POS Depth, added to Position; 0..1 sweeps the table), audio `OUT` (`outNode`, gain 0.5). **Controls**: `Table` menu (`basic` Sine → Triangle → Saw → Square, `vocal` vowels A E I O U as two formants on a 130 Hz note, `digital` a narrow band of harmonics climbing from 2 to 48 over a quiet fundamental, `organ` 8 drawbar settings on harmonics 1, 2, 3, 4, 5, 6, 8, `pwm` a pulse narrowing from 50% to 4%, `draw` Draw (your own wave): frame t blends a sine (t = 0) into the drawn wave (t = 1)), `Position` (0-100%, step 0.1), `Warp` (0-100%), `Unison Voices` (`voices`, 1-7, 1), `Unison Detune` (`detune`, 0-50 cents, 15), `Frequency` (20-2000 Hz, 220), `Octave` (-3..+3), `Tune` (±100 cents), `POS Depth` (0-100%, 100). **Tables** are built on the main thread (`WavetableModule.buildTable`, cached per table and sample rate) from per-harmonic sine / cosine recipes (`WT_TABLES`): 8 frames × 10 band-limited levels × 2048 samples; level k holds harmonics up to `min(256, 0.45 × sampleRate / (40 Hz × 2^k))`; each frame is scaled to a peak of 1 using level 0. The table is posted to the AudioWorklet `wavetable-processor` (from a string through a Blob URL, one shared promise) whenever Table changes. **Worklet** params: `freq`, `fm`, `pos`, `posmod` (a-rate; `PITCH`, `FM` and `POS` are connected into `freq`, `fm`, `posmod`), `ratio` = 2^(Octave + Tune/1200), `warp`, `voices` and `detune` (k-rate). Unison: voice v of n plays at f × 2^(detune × (2v/(n-1) - 1) / 1200) (evenly spread from -Detune to +Detune cents), each with its own phase (voices after the first start at a random phase), and the sum is scaled by 1/√n. Per sample: f = freq × ratio + fm; level = ceil(log2(|f| × highest voice ratio / 40)) clamped to 0..9; each voice's phase accumulates its frequency / sampleRate; Warp is phase distortion (`k = 0.5 - 0.45 × warp`; phase < k maps to 0..0.5, the rest to 0.5..1); position = clamp(pos + posmod, 0, 1) picks two neighboring frames, read with linear interpolation and crossfaded. About every 2048 samples the worklet posts the current position when it moved. **Display** (`canvas.wt-display`, 480 × 240 drawn at 100% × 120 px): the 8 frames of level 0 stacked in pseudo-3D (first wave front-left-bottom, last back-right-top, muted lines), and the wave playing now (with Warp applied) in the primary color at its place in the stack; redrawn on Table / Position / Warp changes and on position messages. **Draw table**: the card keeps a drawn cycle of 128 points (-1..1, starts as a saw, `WT_DRAW_N`); while Table is Draw the display shows it flat (text color, 3 px, with a midline) with the wave playing now over it (primary, 2 px), the canvas gets `.wt-drawing` (crosshair, `touch-action: none`) and the hint `div.wt-hint` under it is shown ("Draw a wave with the mouse or pencil. Position 0% plays a sine, 100% your wave."). Drawing (pointer events with pointer capture, propagation stopped so the canvas does not pan) sets every point between the last and the current x (linear); on release the drawing is turned into harmonics 1-63 by a plain DFT (`waveToHarmonics`, DC dropped), the Draw table is rebuilt (not cached; `buildTable(name, sampleRate, drawn)`) and posted to the worklet. State: the params plus `drawn` (128 numbers, 3 decimals).
- **`PolySynthModule.js`** (template module, type `polysynth`, Sidebar group Sound Sources, 240 px card): a complete polyphonic synth. Also defines `PolyNoteBus` (`window.PolyNoteBus`, used by the Keyboard). **Jacks**: `NOTES` (input, signal `gate`; its input node is a plain object with `noteOn(note, freq)`, `noteOff(note)`, `allNotesOff()`), audio `OUT` (`outNode`, gain 0.35 × Level). **Controls**: `Voices` (1-8, 8), `Waveform` menu (`wave`: sawtooth, square, triangle, sine, or a Wavetable Osc table: `wt_basic`, `wt_vocal`, `wt_digital`, `wt_organ`, `wt_pwm`; the Draw table is not offered), `Position` (0-100%, step 0.5, 0) and `Warp` (0-100%, 0), both `disabled` while a plain wave is chosen, `Detune` (0-50 cents, 8; osc 1 at -Detune/2, osc 2 at +Detune/2), `Cutoff` (`cutoff` 0-100 → 60 × 200^(v/100) Hz, i.e. 60 Hz to 12 kHz, readout in Hz / kHz, 45), `Resonance` (`reso`, Q 0-20, 2), `Filter Env` (`filterEnv` 0-100%, 40: the filter opens to Cutoff × 2^(6 × Filter Env), max 18 kHz, at the top of the attack), `Attack` (1-3000 ms, 10), `Decay` (10-3000 ms, 400), `Sustain` (0-100%, 60), `Release` (10-5000 ms, 500), `Level` (0-100%, 70). **Voices**: 8 voices built once and always running, each two `OscillatorNode`s → GainNode 0.5 → lowpass `BiquadFilterNode` → amp GainNode (0 when silent) → `outNode`. Note on: the voice is chosen as the same note if it still sounds, else a free voice (released and past its release time), else the one released longest ago, else the oldest held note (stolen: a 6 ms fade to 0 first); only the first `Voices` voices are used. Amp: hold the current value (`cancelAndHoldAtTime`, or `cancelScheduledValues` + `setValueAtTime(value)` where missing), linear ramp to 1 over Attack, then `setTargetAtTime(Sustain, end of attack, Decay / 4)`; the filter frequency goes from Cutoff, exponential ramp to the peak over Attack, then `setTargetAtTime` to Cutoff + (peak - Cutoff) × Sustain. Note off: amp and filter `setTargetAtTime` to 0 / Cutoff with time constant Release / 4, the voice is free after Release. **Wavetables** (`applyWave`): a plain wave sets `osc.type`; a table sets one `PeriodicWave` on all 16 oscillators (only when it changed). `PolySynthModule.tableWave(ctx, table, pos, warp)` builds it from `WT_TABLES`, `WT_FRAMES`, `WT_MAX_H` (globals of `WavetableModule.js`, which loads first): `tableFrames(table)` computes the 8 frames' harmonics, each scaled to a peak of 1 (cached per table); the two neighboring frames are blended at Position (like the Wavetable Osc's crossfade); with Warp > 0 one cycle is rebuilt (inverse FFT, 2048 samples), read with the Wavetable Osc's phase distortion (`k = 0.5 - 0.45 × warp`, linear interpolation) and turned back into harmonics 1-256 (FFT, `PolySynthModule.fft` radix-2); then `createPeriodicWave(real = cosine terms, imag = sine terms)`, which the browser band-limits and scales to a peak of 1. Waves are cached by table, Position (3 decimals) and Warp (2 decimals), up to 600 (then the cache is cleared), so an LFO on Position costs about 1 ms per new value. Changing Cutoff / Filter Env / Sustain moves held notes (past their attack) to the new sustain values; lowering Voices releases the voices above it. **Display**: `div.poly-voices`, 8 numbered cells `div.poly-voice` (`.on` while the voice holds a note, `.off` = 30% opacity above the Voices count). State: the params only.
- **`OutputModule.js`**: Final audio destination node. Direct bridge to `AudioContext.destination` with master gain slider, volume level meter, and pass-through `THRU` output.
- **`OscilloscopeModule.js`**: Visual audio monitor (`AnalyserNode`). Real-time oscilloscope waveform rendering on HTML5 Canvas.

### Control & Interactive Signal Modules
- **`KeyboardModule.js`**: Virtual musical keyboard interface. On-screen keys and computer keyboard listeners generating standard `PITCH CV` and `GATE` trigger signals (mono, last key wins). Jacks, left to right: `FREQ` (cv, Hz), `GATE` (0/1), `NOTES` (`data-port-type="gate"`, `data-port-name="notes"`, the `noteBus`, a `PolyNoteBus`: every held key as note messages, see the NOTES convention in section 4; `updateOutput()` calls `noteBus.update(activeKeyOrder)` on every change, `cleanup()` calls `noteBus.disconnect()`), `BEND`. The on-screen keys use pointer events (the keys container has `touch-action: none`): each pointer (mouse, every iPad finger, the pencil) holds its own key under the source id `ptr_<pointerId>` (`pointerKeys` map), so several fingers play a chord; `pointermove` / `pointerup` / `pointercancel` are on `window`, and moving a pointer to another key (found with `document.elementFromPoint`) releases its old key and presses the new one.
- **`SequencerModule.js`**: 8/16 Step Sequencer. BPM tempo control, direction modes, step pitch sliders, ON/OFF step switches. Outputs `PITCH CV` (Hz: `110 * 2^(round(step.pitch * octaveRange * 12) / 12)`: the step slider is snapped to the nearest semitone, so every step plays an equal-tempered note with A = 440 Hz; with `octaveRange: 1` a step pitch of `n/12` is exactly `n` semitones above A2) and `GATE` signals. `setState` also updates the BPM and OCT labels. `CLOCK` output (`data-port-id="clock"`, `data-port-type="gate"`, `clockNode`): a pulse half a step long on every step while playing, active or not (for the Stereo Delay's CLOCK).
- **`RibbonModule.js`** (template module, type `ribbon`, Sidebar group Controllers & Sequencing, 300 px card): a rainbow strip (`canvas.ribbon-strip`, CSS height 100 px, `touch-action: none`) played with the mouse, a finger or the iPad pencil (Pointer Events with pointer capture, one pointer at a time). Left to right sets the pitch: `midi = Base Note + x × Range × 12` (rounded to whole semitones when Snap is on), output in Hz (`440 × 2^((midi-69)/12)`) like Keyboard FREQ, so it plays in tune into Oscillator PITCH; Glide (ms) is the pitch slew (`setTargetAtTime`, time constant glide/3). Outputs (all `ConstantSourceNode`): `PITCH` (Hz), `GATE` (1 while touched; with Hold on it stays 1 after lifting until Hold is switched off), `Y` (touch height 0..1 from the bottom) and `PRESS` (pencil `pressure` 0..1; mouse and finger give 1), both multiplied by `Y / Press Range` (x1..x2000; x1 suits VCA CV, ~1000 suits Filter CUT MOD). On release (Hold off) the gate closes and Y / PRESS return to 0; the pitch stays so the note's release is in tune. Params: Base Note (MIDI 24-72, readout as note name, default C3), Range (1-5 oct, default 2), Glide (0-500 ms, default 20), Y / Press Range, Snap and Hold toggles. Display: the strip is a red-to-violet gradient (brighter while touched) with a thin line per semitone and a stronger line per C, a white position line, and while touched a dot at the touch height whose size follows pressure; a `Note` readout above shows the current note (`-` when silent). Slider modulation source: `getKnobModValue(fromPortInfo)` returns `x × 2 - 1` for PITCH (both ways around the slider's value), and `y`, `pressure` or gate 0/1 for Y, PRESS and GATE (they only push the slider up, so at rest it sits at the user's value); `getKnobModDepth()` is 1.
- **`DrumMachineModule.js`** (template module, type `drums`, aliases `drum_machine`, `drummachine`, Sidebar group Controllers & Sequencing, 760 px card `.dm-card`): a four-row step drum machine in the style of the classic Roland machines, every sound synthesized (oscillators, a shared 2 s white-noise buffer, Biquad filters, envelopes), no samples. **Top bar** (`.dm-top`): `Play` / `Stop` `.action-btn` (`.active` while playing), Tempo slider 40-240 BPM with a number box (`input.dm-bpm`, Enter or leaving the box applies it; its keydown is stopped so the Keyboard module and app shortcuts ignore typing), Swing 0-100% (every second 16th is delayed by `swing% × half a step`), `Bars: n` with `Add Bar` / `Remove Bar` (1-4 bars, default 2; steps beyond the shown bars are kept). **Rows** (`.dm-row`): Kick, Snare, Hi-Hat, Cymbal. Each has a name, a Sound menu, an `Edit` / `Done` button (opens the row's sliders, and the Custom panel when Sound is Custom; closed by default so the card stays small; `.dm-small-btn.active` while open; not saved), a `Clear` button, its own `IN`, `TRIG` and `OUT` jacks (`inline` jacks at the right of the row head, which has 14 px bottom margin for the jack labels), a step grid (`.dm-grid`, one `.dm-bar` of 16 `button.dm-step` per bar, 18 × 26 px, extra gap on each beat (`.dm-beat`), bars wrap after two), and five sliders Tune (-12..+12 st), Decay (20-300%), Tone (0-100%, filter brightness ×0.25..×4 or click / noise amount), Level (0-100%, default 80) and Pan (L100..R100). Tapping a step cycles off → on (`.dm-on`, half-tint) → accent (`.dm-accent`, full primary color, velocity 1.0 instead of 0.7) → off; switching a step on while stopped plays it once. The playing step is outlined (`.dm-now`). **Sounds** (`DrumMachineModule.VOICES`): Kick `808` (sine 50 Hz, pitch drop ×2.6 over 60 ms, 0.55 s), `909` (55 Hz, ×4.2 over 30 ms, 0.32 s, louder noise click), `606` (68 Hz, short); Snare `808` (triangle 180 + sine 330 Hz body and high-passed noise), `909` (brighter, longer noise plus a 260 → 180 Hz pitch-drop body), `Rimshot` (square 500 + triangle 1720 Hz through a band-pass, 30 ms), `Clap` (three noise bursts 11 ms apart and a tail through a 1.1 kHz band-pass); Hi-Hat `808 Closed` / `808 Open` (the 808's six square oscillators 205.3, 304.4, 369.6, 522.7, 540, 800 Hz through a 10 kHz band-pass and a 7 kHz high-pass; 50 ms / 420 ms), `909 Closed` / `909 Open` (mostly noise with some metal); Cymbal `808 Cymbal` (metal through 7.1 kHz and 3.44 kHz bands), `909 Crash` (noise and metal, high-passed, 1.5 s), `Ride` (metal through 5.2 kHz plus a 3150 Hz ping), `Cowbell` (squares 540 + 800 Hz through a 2.64 kHz band-pass). Every row also has `Input`: the row's `IN` jack (audio) feeds a persistent chain `inNode` → low-pass (`2500 Hz × Tone`, Q 0.7) → `inVca` (gain 0) → row Level, and each hit opens `inVca` (2 ms rise to the velocity, then `setTargetAtTime(0, …, 0.1 s × Decay)`), so any patched sound (an Oscillator, or an Oscillator through a Filter) plays as that drum. `onInputConnected(<row>_in, connected)` counts the cables: plugging the first one switches the row's Sound to Input (remembering the previous sound), pulling the last one out restores it. Every row also has `Custom`, which shows a dashed panel (`.dm-custom`) with Wave (sine / triangle / square / saw), Pitch (20-2000 Hz), Pitch Env (0-48 st drop to the pitch), Noise (0-100% mix), Attack (0-100 ms), Decay (10-2000 ms) and a resonant low-pass Cutoff (40-16000 Hz) / Resonance; the row's Tune, Decay and Tone still apply. Each hit goes through a per-sound loudness trim (`DM_TRIM`, measured so all sounds peak at a similar level) into the row's Level gain. **Audio graph**: row Level gain → row `OUT` jack and → `StereoPannerNode` (Pan) → 2-channel main bus → `ChannelSplitter` → `MAIN L` / `MAIN R` jacks (bottom row); `CLOCK` (bottom row, gate) pulses for half a step on every unswung 16th while playing; `TRIG` is an output: a `ConstantSourceNode` set to 1 for half a step on every hit (for Envelope GATE IN, so other modules can sound with the drums). **Timing**: a look-ahead scheduler (`setInterval` 25 ms, schedules 120 ms ahead on the audio clock); a `requestAnimationFrame` loop moves the playhead when each scheduled step's time arrives. It does not auto-start on load. **State** (`getExtraState`): `{ tempo, swing, bars, rows: [{ sound, knobs: { tune, decay, tone, level, pan }, custom: { wave, pitch, penv, noise, attack, cdecay, cutoff, reso }, steps: '<64 digits 0/1/2>' }] }`. Default: Kick 808 / Snare 808 / Hi-Hat 808 Closed / Cymbal 808 Cymbal, with a basic groove (kick on beats 1 and 3, accented on 1; snare on 2 and 4; closed hat on every 8th; cymbal on the first step). All sliders have stable ids (`drums_p_<row>_<knob>_<id>`, `drums_p_tempo_<id>`, `drums_p_swing_<id>`), so LFO / Ribbon cables can move them.
- **`StereoDelayModule.js`** (template module, type `delay`, alias `stereo_delay`, Sidebar group Processors & Effects, 460 px card `.sd-card`) with **`delay-worklet.js`** (its `AudioWorkletProcessor` `stereo-delay`, loaded once per context with `audioWorklet.addModule('delay-worklet.js?v=1')`, cached on `ctx.__delayWorklet`; the module's nodes exist at once and the worklet node is connected when it has loaded). **Jacks**: `IN L`, `IN R` (audio; while IN R has no cable, counted by `onInputConnected`, the worklet uses IN L for both sides), `CLOCK` (gate, one pulse per 16th note), `OUT L`, `OUT R`. **Graph**: IN L / IN R → `ChannelMerger` → worklet input 0; CLOCK → worklet input 1; worklet output (2 ch) → `ChannelSplitter` → OUT L / OUT R; IN L and IN R also feed an `AnalyserNode` for the display. **Controls** are a grid (`.sd-grid`, columns name / Left / Both / Right): Time (10-2000 ms; defaults L 375, R 500), Feedback (0-95%, 40), Tone (0-100%, 60), Level (0-100%, 100), Mix (0-100%, 35), each as three sliders with readouts; a Reverse row of three On/Off buttons; a Division row (shown while Sync is on) of three menus (1/16, 1/8, 1/8 dotted, 1/8 triplet, 1/4, 1/4 dotted, 1/4 triplet, 1/2, 1 bar; values in 16ths: 1, 2, 3, 1.333, 4, 6, 2.667, 8, 16; defaults L 1/8 dotted, R 1/4); then `Ping-Pong: On/Off`, `Sync: On/Off` and a clock readout (`Clock: <n> BPM` or `No clock`, after 3 s without pulses). The Both column shows the average of the two sides and sets both sides to its value; Left / Right set one side (slider ids `delay_p_<param>_<L|B|R>_<id>`, all LFO-modulatable). **Sync**: the worklet reports the interval between rising clock edges (> 0.5, 20 ms to 2 s); with Sync on and a clock live (a pulse within the last 3 s), each side's time is `interval × division` (max 2 s), the Time sliders are disabled and their readouts show the synced time; when the clock stops, the sliders unlock and the delay goes back to the manual Time (and locks again when pulses return). **DSP** (per sample, per side): 4.2 s buffers; the delay time glides to its target (60 ms smoothing, so changes bend the pitch like tape); forward read with linear interpolation, or Reverse: chunks as long as the delay, each playing the previous chunk backwards (`read(1 + 2 × phase)`) with 8 ms fades; the repeat goes through a one-pole low-pass at `400 Hz × 2^(Tone × 5.5)` (400 Hz to ~18 kHz); the feedback path removes lows with a 60 Hz high-pass and is written through `tanh` (soft clip; Feedback capped at 0.95). Ping-Pong: the input (L+R)/2 goes into the left line only, and each repeat feeds the other side's line. Output per side = `dry × (1 - Mix) + repeat × Level × Mix`. **Display** (`canvas.sd-display`, 872 × 240 drawn at 100% card width × 120 px): two lanes L / R over 2.4 s; every repeat a single hit makes is a triangle at its time whose height is its level (Feedback^n × Level; forward repeats lean right, reverse repeats lean left; with Ping-Pong they alternate lanes); input hits (a jump in the analyser peak, > 0.03 and 1.6 × the recent level, at most every 80 ms) start a vertical pulse line that runs across at real time and lights each repeat as it passes; with Sync a faint line marks every beat. The first repeat of each side has a round handle whose height shows that side's Feedback: dragging it (mouse, finger or pencil; pointer capture) sets Time from x (or the nearest Division when synced) and Feedback from y; a press elsewhere grabs the lane's handle. **State**: `{ L: { time, fb, tone, level, mix, rev, div }, R: { … }, pingpong, sync }`.
- **`MetronomeModule.js`** (template module, type `metronome`, Sidebar group Controllers & Sequencing, 260 px card `.metro-card`): a metronome and master clock. **Top** (`.metro-top`): `Play` / `Stop` `.action-btn.metro-play` (`.active` while playing) and `Tap` (`pointerdown`; the tempo becomes the average gap of the last up to 5 taps, a gap over 2 s starts over). **Beat lights** (`.metro-lights`): one round `.metro-light` per beat, the first outlined in the primary color (`.metro-first`), the current beat filled (`.metro-now`). **Params**: Tempo slider 20-300 BPM (default 120) with a number box (`input.dm-bpm` inside `.dm-bpm-box`, inserted in `onMount` next to the hidden readout; Enter or leaving the box applies it, keydown is stopped so shortcuts ignore typing; the box follows the slider and LFO modulation), Beats per Bar 1-12 (default 4), Sound select (`click` = 30 ms noise burst through a band-pass at 2.6 kHz / 4.2 kHz accented; `wood` = 60 ms triangle knock 1150 Hz / 1700 Hz with a slight pitch drop; `beep` = 90 ms sine 880 Hz / 1760 Hz), Volume 0-100% (default 70, the CLICK gain), Accent toggle (default On: the first beat of the bar uses the accented pitch and full level, other beats 0.6; no accent when Beats per Bar is 1). **Jacks** (bottom row, no inputs): `CLICK` (audio, a GainNode summing the click voices) and `CLOCK` (gate, a `ConstantSourceNode`, see the CLOCK convention in section 4; listed in the Stereo Delay's CLOCK `guide.match`). **Timing**: same look-ahead scheduler as the Drum Machine (`setInterval` 25 ms, 120 ms ahead, one step = a 16th note = `60 / tempo / 4` s); every step pulses CLOCK, every 4th step plays a click; a `requestAnimationFrame` loop lights the beat when its time arrives. Stop cancels scheduled CLOCK values and sets it to 0. It does not auto-start on load (a preset opened from the Help starts it). **State**: the params only (`{ tempo, beats, sound, volume, accent }`). Sliders have stable ids (`metronome_p_tempo_<id>` etc.), so an LFO can move the tempo.
- **`WebcamModule.js`**: Computer-vision Control Voltage generator. Tracks brightness/motion from webcam feed via HTML5 Video element and outputs dynamic `CV` modulation signal. Supports alias type spawning (`webcam`, `webcam_controller`, `webcam-controller`, `camera`) and includes safe runtime verification of `WebcamModule.js` script presence with explicit DOM/console user warnings if uninitialized.
- **`RecorderModule.js`**: Master audio recorder (PCM capture through a `ScriptProcessor`, normalized to -10 LUFS, encoded as 16-bit stereo WAV at the hardware sample rate). Always saves WAV (the old fake MP3 option, which wrote WAV data under a `.mp3` name, was removed; old patches with `format: 'mp3'` load as WAV). ## 3. Strict UI, Visual & Audio Preferences (Design Rules)

### 1. No Icons in Modules Rule (כלל איסור אייקונים במודולים)
- **חוק ברזל:** אין להשתמש באייקונים או אימוג'ים בתוך רכיבי המודולים (כותרות מודול, כפתורי תפעול, כפתורי מחיקה, תפריט Sidebar, או תוויות פורטים).
- **חלופה:** יש להשתמש בטקסט שמי קריא בלבד (לדוגמה: "Delete" או "X" במקום אייקון פח, "Audio Input" במקום אייקון מיקרופון, "Oscillator" במקום אייקון גל).

### 2. Design System & Theming
- Fully implemented via CSS Custom Properties (`--bg-color`, `--panel-bg`, `--primary-color`, `--panel-border`, `--text-color`).
- Clean White light theme as default with full Dark Theme support toggled via `.dark-theme` on `<body>`.
- Modular cards use explicit shadow layers (`var(--shadow-sm)`), smooth border transitions (`var(--transition-fast)`), and rounded corners (`var(--radius-lg)`).

### 3. Module Card Structure & Constraints
- **Card Width**: Standard modules must maintain a `min-width: 220px` (or `width: 220px`). Large modules (e.g., Granular Engine) use wide double-panel grid layouts (`width: 500px`).
- **Vertical Flex Layout**: Card body (`.node-body`) uses flexbox layout (`flex-direction: column`, `padding: 12px`, `gap: 10px`).
- **Ports Container Docking**: The ports section (`.ports-container`, `.ports-row`) **must always** use `margin-top: auto` to dock ports cleanly at the bottom of the card, preventing text overlapping or card overflows.
- **Control Uniformity**: Standard buttons use `.action-btn`. Continuous range inputs (`input[type="range"]`) must always include an accompanying numeric text readout displaying the active unit (`Hz`, `ms`, `%`, `dB`).

### 4. Accessibility & Focus Indicators
- Clear keyboard focus indicators (`*:focus-visible`) styled with `outline: 2px solid var(--primary-color)`.
- Customized scrollbars (`::-webkit-scrollbar`) styled to blend seamlessly with active themes.

### 5. Language Rule
- The whole site UI is English only: toolbar, sidebar, modules, notifications, `alert`/`confirm` dialogs, and `<html lang="en">`.
- Hebrew exists only inside the Help manual (`helpData.js` `he`), as an optional second language the user switches to with the Hebrew button. Code comments may stay in Hebrew.

### 6. Notifications
- `app.js` `showNotification(message)` is the single notice mechanism: a `div#synth-toast-notification.app-toast` (styled in `styles.css`) at the bottom center, theme-aware panel colors with a primary-color left border, plain text, no icon, fades in via the `.visible` class and hides after 6 s.

## 4. Signal Flow & Port Color Coding System

### Signal Types & Port Specifications
- 🟢 **Audio Signals (`data-port-type="audio"`):** Green (`#10b981`). Sound-generating audio paths (e.g., VCO Out &rarr; VCF In &rarr; VCA In &rarr; Reverb In &rarr; Main Output).
- 🟡 **Gate / Trigger Signals (`data-port-type="gate"`):** Yellow/Orange (`#f59e0b`). On/Off timing pulses generated by Keyboard or Sequencer to trigger Envelope attack phases.
- ⏱ **Clock convention (`CLOCK` jacks, `data-port-id="clock"`, `data-port-type="gate"`):** every tempo source outputs one pulse per 16th note while it plays: the value goes to 1 at the step's (unswung) time and back to 0 half a step later (a `ConstantSourceNode` scheduled on the audio clock). Tempo followers measure the time between rising edges (crossing 0.5) to get seconds per 16th (BPM = 60 / (interval × 4)) and treat 3 s without a pulse as no clock. Sources: Metronome `CLOCK`, Drum Machine `CLOCK`, Sequencer `CLOCK`; followers: Stereo Delay `CLOCK`. Any new tempo source must follow this, and add its `<type>:out:clock` key to the followers' `match` lists in `portGuide`.
- 🎹 **NOTES convention (note messages, not sound)**: a NOTES cable carries every held key. The source jack's node is a `PolyNoteBus` (`PolySynthModule.js`): `connect(sink)` / `disconnect(sink)` are called by `app.js` exactly like for an audio node (the sink is the target module's input object; a target without `noteOn` is ignored). On `connect` the sink gets `noteOn` for keys already held; `update(list)` diffs the held keys (by MIDI note number, from `{ midiNote, freq }` items) and sends `noteOff(note)` / `noteOn(note, freq)` (also when a held note's Hz changes); `disconnect` sends `allNotesOff()`. The cable is drawn in the gate color (`data-port-type="gate"`). Source: Keyboard `NOTES`; sink: Poly Synth `NOTES`.
- 🔵 **Control Voltage / Modulation (`data-port-type="cv"` / `"fm"` / `"cutoff"`):** Blue (`#6366f1`). Continuous modulation voltages (e.g., Pitch CV, Envelope CV Out, LFO Out, Webcam CV Out).

### Standard Patching Flow
1. **Pitch / Gate**: Keyboard (`FREQ`) / Sequencer (`PITCH CV`) &rarr; VCO (`PITCH`) | Keyboard / Sequencer (`GATE`) &rarr; Envelope (`GATE IN`).
2. **Audio Path**: VCO (`AUDIO OUT`) &rarr; VCF (`AUDIO IN`) &rarr; VCA (`AUDIO IN`) &rarr; Output (`AUDIO IN`).
3. **Modulation Path**: Envelope (`CV OUT`) &rarr; VCA (`CV IN`) | LFO (`CV OUT`) &rarr; VCF (`CUTOFF CV`).

## 5. Interaction & Viewport Controls

1. **Canvas Panning**: Holding `Cmd` (macOS) or `Ctrl` (Windows) + Left-Click dragging pans the workspace viewport.
2. **Module stacking**: the module the user last pressed (anywhere on its card) is raised above all others (`bringToFront`, increasing inline `z-index` from 21), so a dragged module never slides under another.
2c. **Resizing modules**: every card gets a `.module-resize-handle` grip (22 px, bottom-right corner, two diagonal lines) added in `makeDraggable`; dragging it with mouse, finger or Apple Pencil changes the card's width/height (divided by the zoom `scale`), never below the CSS `min-width` and never shorter than the card's own content (measured with `height: auto`), so the jacks are never cut off. The browser's own `resize: both` corner is turned off (`resize: none`) because it does not work with touch. Hidden in Play Mode. Sizes are not saved in patches.
2b. **Zooming**: Controlled via Toolbar Zoom buttons or mouse wheel modifiers, scaling `#workspace-viewport`.
   - **iPad / touch**: pinching with two fingers on the empty workspace zooms the app view around the fingers (and moving the two fingers pans it), handled with pointer events in `bindCanvasInteractions` (`touchPoints`, `pinch`). The Apple Pencil (`pointerType: 'pen'`) never pinches. The browser's own page zoom is blocked: `touch-action: none` on `html`, `body` and `#canvas-container`, `preventDefault` on Safari's `gesturestart/gesturechange/gestureend` and on multi-finger `touchmove`. Scrollable areas (Sidebar, help tabs and help content) use `touch-action: pan-x pan-y` so they still scroll. The viewport meta also has `maximum-scale=1.0, user-scalable=no`.
   - **Stuck page zoom**: Safari can reopen the page still zoomed in from before, pushing the menus off screen. `resetPageZoom()` (called from `bindCanvasInteractions`) briefly rewrites the viewport meta on load and on `pageshow` so Safari returns to normal size. While `visualViewport.scale > 1.01` the `html.page-zoomed` class is set: it switches `touch-action` to `manipulation` and stops blocking Safari's gesture events, so the page can be pinched back out by hand; the lock returns once the page is at normal size.
   - Moved Sidebar / Toolbar positions are clamped back on screen on load and on every window `resize` (e.g. rotating the iPad).
   - **No accidental text selection**: `* { -webkit-user-select: none; user-select: none; -webkit-touch-callout: none; -webkit-tap-highlight-color: transparent }` (Safari needs the `-webkit-` prefix); only text inputs and textareas allow selection.
3. **Presentation / Play Mode**:
   - Toggled via `Play Mode` button in Toolbar (`body.presentation-mode`).
   - Hides ports, wire connections (`#connections-canvas`), delete buttons, and module spawn Sidebar.
   - Disables card dragging and cable creation while keeping sliders, knobs, buttons, and visual meters fully playable for live performance.
4. **Cables**: a cable from LFO OUT can also be dropped on any slider of another module, which then moves up and down around the value you set (sliders it can be dropped on get a dashed outline while dragging; see `modulation.js`). Otherwise, drag from a port to a port to connect (an output can feed several cables; `Shift`+drag from an output moves its last cable); connected ports take their cable's color; drag a plugged cable end into empty space to unplug. Click a cable on the empty workspace to select it, click it again (or press `Delete`) to delete it. The `Cables: Front/Back` toolbar button moves all cables in front of or behind the modules. In Front mode a cable is still hidden where a module stacked above it covers it (`getCardStack`, `getCoveringRects` in `drawConnections`, using canvas clip regions): any module above both of its modules, and any module above the lower one of its two modules that covers that module's jack; in that case only an 18 px stub shows at the visible jack. Pressing a module (`bringToFront`) redraws the cables.
5. **Moving the menus**: drag the Sidebar by its `Modules` title and the Toolbar by its `Move` label; double-click to return it to its default corner.
6. **Undo / Redo**: the arrow buttons at the start of the Toolbar, or `Cmd+Z` / `Cmd+Shift+Z` (`Ctrl` on Windows, `Ctrl+Y` also redoes). Covers adding, moving and deleting modules, cables, every knob/slider/menu value inside modules, loading a preset or file, and Clear. The Keyboard module ignores key presses held with `Cmd`/`Ctrl`/`Alt`, so `Cmd+Z` does not play a note.
7. **Interactive Tooltips / Jack hints**: Toggled globally via `#toggle_tooltips_btn`. Hovering a jack shows the `portGuide.js` card (what it is, where to connect it); dragging a cable highlights recommended and valid destinations and fades the rest.

## 6. Web Audio Architecture & Audio Engine

- **Dynamic Hardware Sample Rate Detection**: Unconstrained `AudioContext` instantiation dynamically locks onto host interface sample rates (44.1kHz, 48kHz, 96kHz) without hardcoded assumptions, eliminating pitch and playback speed distortion.
- **AudioContext Lifecycle**: anything other than `running` / `closed` counts as asleep (`suspended`, and iPad Safari's `interrupted` after switching to another app). `audioEngine.wake()` resumes it; it runs on every `pointerdown` / `touchend` / `keydown` (capture phase, permanent) and when the page becomes visible again (`visibilitychange`, `pageshow`). If the sound is still off 700 ms after returning (Safari only restarts sound from a tap), and it had played before (`hasPlayed`, set from `statechange`), a toast says "Tap anywhere to turn the sound back on." `app.ensureAudioContextRunning()` uses the same rule. The Mic module (`watchMicInterruptions`) reconnects the microphone on return when its track ended while the page was hidden.
- **Connection Mechanics & Auto-Alignment**: Cables rendered on canvas as dynamic Bezier paths connecting source output ports to target input ports/AudioParams. Automatically updated in real time via `ResizeObserver` whenever module card geometry or internal UI elements undergo layout shifts.
- **Input notifications**: after `connectAudio()` connects a cable, and after `disconnectAudio()` removes one, `app.js` calls `notifyInputConnection()`, which calls the target module's optional `onInputConnected(portKey, connected)` (portKey = `data-port-id` || `data-port-name` || `data-port-type`). The Oscillator uses it for PITCH.
- **Module creation order** (`createModule`): build the card, `bindEvents`, attach drag and port events, append the card to the page, then `setState(state)`, so modules that look up their own controls with `document.getElementById` also update their sliders and labels.
- **CV scales are not uniform** (know this when writing presets): Envelope ENV OUT 0..1; Keyboard/Sequencer gate 0/1; Keyboard FREQ and Sequencer PITCH in Hz; LFO OUT ±(depth% × 2) i.e. depth 50 = ±100; Webcam X/Y 0..cvDepth (1000) and MOTION 0..1. Filter CUT MOD multiplies its input by Mod Depth (Hz), so an LFO into the filter needs a small LFO depth (e.g. depth 1 with Mod Depth 300 = ±600 Hz).
- **Safe Routing Protocol**: Patch cable creation uses `getNodeOrParamForPort()` wrapped in `try/catch` blocks to safely handle audio-to-audio node connections and audio-to-AudioParam CV modulation.

## 7. Patch Persistence & Module Protocol (JSON Schema)

### Saving and loading files
- **Save** (`exportPatch()` in `app.js`) gets the patch object below from `getPatchObject()` and turns it into a `Blob` (`application/json`) named `synth_patch_<timestamp>.json`. Patches are not stored inside the site; they are always a file.
- **On iPad / iPhone** (user agent `iPad|iPhone|iPod`, or `MacIntel` with `maxTouchPoints > 1` for iPadOS) and when `navigator.canShare({ files })` is true, Save opens the system share sheet (`navigator.share`) so the user picks **Save to Files** (or AirDrop, Mail, etc.). Cancelling the sheet does nothing; any other share error falls back to the download below.
- **Everywhere else** `downloadBlob()` downloads the file through a temporary object URL (revoked after 10 s) and shows the toast `Patch saved as <name> (in your Downloads folder).`
- **Load** opens the hidden `#import-patch-input` (`accept=".json,application/json"`), reads the file with `FileReader`, and passes it to `loadPatchData()`.

### Schema Format (`v1.0`)
```json
{
  "version": "1.0",
  "timestamp": "2026-10-02T10:00:00.000Z",
  "theme": "light",
  "modules": [
    {
      "id": "osc_1",
      "type": "oscillator",
      "x": 100,
      "y": 150,
      "state": { "frequency": 440, "waveform": "sawtooth" }
    }
  ],
  "connections": [
    {
      "fromNode": "osc_1",
      "fromPortInfo": { "type": "audio", "portIndex": 0 },
      "toNode": "out_1",
      "toPortInfo": { "type": "audio", "portIndex": 0 }
    }
  ]
}
```

## 8. Repository, Deployment & Working Rules

- **Source of truth:** GitHub repository `noambartov/sound-playground`, branch `main`. Older local copies (e.g. the iCloud folder `sound playground v_4`) are not updated automatically.
- **Live site:** GitHub Pages, deployed from `main` / root. URL: https://noambartov.github.io/sound-playground/. Every push to `main` redeploys automatically.
- **No build step:** plain static files; `index.html` is the entry point.
- **Repo housekeeping files:** `README.md` (short description), `.gitignore` (ignores macOS `.DS_Store`), `CLAUDE.md` (working rules for Claude sessions, including that deploys need no PWA cache bump), `ROADMAP.md` (the owner's backlog of future ideas plus a market review; ideas there are not built until the owner approves, and new ideas from any thread are added there).
- **Publish rule:** every finished change is merged into `main` right away, without waiting for the owner to ask, because the live site is the owner's only way to see changes. Test in a headless browser first. After merging, wait until the `pages build and deployment` GitHub Actions run whose `head_sha` matches the merge commit reports `completed` / `success` (e.g. `https://api.github.com/repos/noambartov/sound-playground/actions/runs?per_page=1`), and only then tell the owner the site is ready (usually 1-2 minutes). After a deploy, a hard refresh (Cmd+Shift+R) may be needed in a browser tab; the installed iPad app shows its own "new version" notice instead; the `?v=` numbers on `styles.css` / `app.js` in `index.html` must be bumped on every change to those files so browsers fetch the new version.
- **Installable app (PWA):** the site can be added to the iPad home screen (Safari: Share > Add to Home Screen) and then opens full screen in its own window and works offline.
  - `index.html` `<head>`: `<link rel="manifest" href="manifest.webmanifest">`, `theme-color` `#0f172a`, `mobile-web-app-capable` and `apple-mobile-web-app-capable` `yes`, `apple-mobile-web-app-title` "Sound Playground", `apple-mobile-web-app-status-bar-style` `default`, `apple-touch-icon` `icons/icon-180.png`, `icon` `icons/icon-192.png`. `pwa.js?v=1` is the last script.
  - `manifest.webmanifest`: name / short_name "Sound Playground", `start_url` and `scope` `./` (works under the `/sound-playground/` Pages path), `display: standalone`, `orientation: any`, background and theme `#0f172a`, icons 192 and 512.
  - `icons/icon-180.png`, `icon-192.png`, `icon-512.png`: full-bleed square (iOS rounds the corners), background `#0f172a`; a thick sky-blue (`#38bdf8`) sine wave, 1.5 cycles, across the upper half with round ends; below it two jacks (light `#e2e8f0` rings with a `#334155` center) joined by a sagging amber (`#f59e0b`) cable. Drawn at 1024 px with Pillow (circles stamped along each path) and downscaled.
  - `sw.js` (service worker, cache `sound-playground`). **Zero maintenance: no version number or file list to update when the site changes.** The file list is read live from `index.html`: every `src="..."` / `href="..."` without `:` or `#`, plus any `addModule('...')` path found in those scripts (worklets like `delay-worklet.js`). Install: caches all of them, `skipWaiting()`; activate: `clients.claim()`. Fetch (same-origin GET, never `sw.js` itself): **network first** with `cache: 'no-cache'` (so online always gets the latest deploy), the response is stored (older copies of the same path with another `?v=` are deleted); page navigations always fetch and store `./` (index), and a redirected page answer is re-wrapped because Safari refuses redirected responses from a service worker. If the network fails, or gives nothing for 4 s, the stored copy is served (`ignoreSearch` fallback, so a bumped `?v=` still finds the old file offline). Message `check-update`: re-fetches the whole list, compares each file's bytes with the stored copy, stores what changed, and if anything changed posts `update-available` back to the page.
  - `pwa.js`: registers `sw.js` (only on http/https). Asks the service worker `check-update` 15 s after load, every 10 minutes, and whenever the app comes back to the foreground (`visibilitychange`), at most once a minute; nothing is checked once the notice is showing. On `update-available` it shows the notice (section 3.6). **Refresh** keeps the work: if there are modules it stores `synthApp.getPatchObject()` (the same object Save writes, from `app.js`) in `sessionStorage` key `sp_carry_patch`, then reloads; on `load` the patch is restored with `loadPatchData` (Output volume starts at 0 as for every load) and the toast says "Updated to the new version. Your patch was kept; raise Master Volume on the Output module to hear it." Exposes `window.showUpdateNotice()` for testing.
  - Result for deploys: the installed app picks up every push to `main` by itself; an app left open shows the notice within ~10 minutes or the next time it is brought to the front, and a fresh launch loads the new version directly. In a normal browser tab the same service worker makes a plain refresh load the latest files.
- **Documentation rule:** every change to a file or to a foundational setting must be reflected in this `architecture.md` in the same commit, so that this document always holds everything needed to rebuild the site from scratch.
